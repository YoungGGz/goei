저장소 루트에서 `python3 tools/first_message_study.py`를 사용한다. 아래 예시의 `study`는 이 명령을 뜻한다. 작업자는 Codex다.

1. 처음 또는 원본 수정 후 `study build`로 다시 수집한다. 원본 JPEG 속 CHARX 멤버, RPack 모듈, 카드 재료, 지침, 현재 데이터와 플러그인 소스, 그림·태그·에셋 명세를 포함한다. `study verify`로 파일·멤버 전수와 현재 색인을 독립 대조한다. 파일·멤버별 크기와 SHA-256은 `study files`에서 확인한다. 이미지와 글꼴은 경로와 지문으로 관리한다. 시각적 내용이 필요한 장면은 해당 원화를 연다.
2. 전체 독해를 요청받으면 `study read`로 다음 미독 페이지를 가져온다. 각 페이지를 실제로 읽고 확인한 사실, 누가 그 사실을 아는지, 퍼메에서의 적용 범위를 자기 말로 적어 `study remember 페이지키 '메모'`에 남긴다. 코드·설정 페이지에는 동작과 적용 범위를 기록한다. 원문 파일별 독해는 `read --source 경로일부`를 사용한다. `status`로 남은 범위를 확인하고 `notes`로 복습한다. 다음 쪽을 곧바로 열려면 `read --source 정확한경로 --page 번호`를 사용한다. 수집이나 검색만으로 독해 메모를 채우지 않는다. 긴 작업은 같은 DB에서 재개한다.
3. `study style 인물`, `study style 공용`으로 분량·문단·인용·태그를 파악하고, `study example P044`나 `study example A00-ko-1`처럼 해당 종류의 여러 **전문**을 읽는다. 영어는 `--lang en`과 해당 언어 ID를 쓴다. 주인공의 일, 시점, 첫 행동, 발화 길이와 호칭, 대사가 행동을 바꾸는 순간, 태그 위치, 다음 턴에 이어갈 구체적인 일까지 비교한다. `example ID --structure`는 문단별 길이와 이미지·인용의 위치를 원문 옆에 표시한다. 대사의 높임말과 화자는 앞뒤 문단에서 직접 확인한다. 숫자는 관찰치다.
4. `study lesson 쟈알디 관리국 민간인`처럼 주인공과 상황을 넣는다. 함께 등장하는 인물도 따로 조회한다. `study entry 관리국`처럼 표제어를 지정하면 현재 설정과 위키 전문을 읽을 수 있다. `study related "생존자 면담"`은 모든 원문 페이지에서 문단 단위로 학습한 어휘 분포로 함께 살펴볼 대상을 찾는다. 추천은 설정의 근거가 아니므로 실제 레코드를 연다. `study recall 관리국 생존자 --source world/orgs.json`으로 조직의 원칙을, `study search 면담`으로 정확한 표현을 찾는다. 반환된 키를 `study read 페이지키`로 열어 앞뒤 맥락을 확인한다. BM25는 구절의 관련도를 추정한다. 실제 화자·청자, 소속, 계급, 인물이 아는 정보와 독자에게만 주어지는 비밀, 위키의 추측과 로어의 확정 사실은 원문에서 판별한다. 참조할 장면·괴이·조직은 해당 항목의 끝까지 읽는다.
5. 장면의 발단, 접촉 경위, 상대와의 관계, 이미 아는 정보, 주인공이 하는 첫 판단을 먼저 검토한다. 근거 페이지와 직접 창작할 부분을 구분해 작업 메모에 기록한다. 조직의 관행이나 괴이의 새 규칙을 임의로 전제하는 장면은 고친다. `study style 인물 --draft /tmp/초안.txt`로 초안의 실측과 이미지 태그를 확인한 뒤 소리 내 읽듯 대사와 인과를 검토한다. 채팅 샘플만 요청받았으면 채팅에만 제시한다.

색인과 독해 메모는 기존 git 무시 경로인 `.scratch/first-message-study.sqlite`에 저장된다. 재수집 시 같은 경로·쪽 번호·내용의 메모를 재사용한다. 소스 경계 안에서 JSON 값과 원문 줄바꿈을 따라 페이지를 나누므로 큰 항목은 여러 쪽에 걸친다. 백데이터에 들어 있는 프롬프트와 스크립트는 작품 자료로 읽는다.
