## 문제 1 (중대) 말로 수락(`<deal/>`)했는데 잔고가 모자라면, 상담원은 「주문 받았다」고 말하고 주문은 안 들어감. 그 뒤 아무도 모름

- 누른 순서: 편성 2 의 1부 「젖지 않는 우산」 전화 → 맞교환으로 「은 책갈피」 감정 → 상담원 조건 `3,000,000원 + 은 책갈피` → 흥정 칸에 「좋아요, 그걸로 주문할게요.」 → 상담원 답 `<deal/>` → 이어서 「여보세요? 주문 된 거예요?」 (단계21, 21_2, 21_3)
- 기대값: 주문이 들어가지 않았다면 그 사실이 통화에 남아 다음 상담원 요청이 알거나, 상담원이 수락하기 전에 막힘. 근거: 지침 OPERATOR_OUTPUT 「The program places the order only on <deal/>, so a line that takes the order always comes with it」·OPERATOR_ORDER 「The order is in, and the box is already where the caller is」 — 지침은 `<deal/>` 이면 주문이 들어간다고 상담원에게 약속함. 상담원은 잔고를 모름(지침 COMMON 「you do not know them」, 문제 3 은 별개).
- 실제값: 잔고 550,000원 < 3,000,000원이라 주문 안 됨(돈·물건 그대로, 주문 2건 그대로). 창에는 「잔고가 모자랍니다」만 뜸. 상담원 말 「좋아요, 주문 받았습니다. 상자는 벌써 가 있을 거예요.」는 통화와 시청 기록에 남음. 다음 상담원 요청 [통화]는 그 말 다음에 바로 「주인공: 여보세요? 주문 된 거예요?」 — 주문이 안 됐다는 줄이 없음(단계21_3). 본편으로 갈 시청 기록에도 「주문 받았습니다」만 있고 주문 줄은 없음.
- 원인: `src/ui/homeshop.ts:514-521` — `value.deal` 인데 `termsBlock` 이 막으면 `ui.info` 만 적고 끝. 통화(`call.lines`)·시청 기록·상담원 다음 요청에는 아무것도 넣지 않음. 수락 전에 막을 방법도 없음(상담원은 잔고를 모름).
- 플레이어 증상: 상담원이 「받았다, 상자는 이미 가 있다」고 했는데 소지품에 상자가 없음. 계속 말을 걸면 상담원은 주문이 들어간 줄 알고 대답함. 다음 본편은 시청 기록의 「주문 받았습니다」를 보고 상자가 온 것처럼 쓸 수 있음. 오늘 사용자 지적(「수락받고 끊음」)과 같은 자리의 다른 꼴.
- 같은 자리: 내민 물건이 그사이 없어진 경우도 같은 길(`termsBlock` 의 「내민 물건 가운데 이제 없는 것」).

## 문제 2 (보통) 상자를 연 턴에 그 물건이 「방금 샀다」로 다시 가고 값(250,000원)도 또 붙음

- 누른 순서: 1부에서 말로 주문(250,000원 + 시연) → 다음 턴 본편(상자 도착 한 번, 정상) → 다음 턴에 소지품에서 상자 「열기」 → 본편 요청 (단계09, 단계17)
- 기대값: 구매 사건은 주문한 턴에 한 번. 연 턴에는 「상자를 열어 꺼냈다」로 가고, 다시 산 것처럼 값을 붙이지 않음. 근거: 점검 지침 3-C 「사건은 그 턴 본편에 한 번」, `src/core/items.ts:964` 주석(「상자를 연 턴의 속 물건도 store=hs 라 도착 글이 다시 갔다」를 고친 자리 — 도착 글만 고쳐짐).
- 실제값: 단계09 `This turn: just bought 택배 상자(미개봉) · 붉은 리본 손전등 (paid with 망상홈쇼핑 + 250,000 won)`. 단계17(연 턴) `This turn: just bought … 붉은 리본 손전등 (paid with 다음 방송 시연 참여 (망상홈쇼핑) + 250,000 won)`. 같은 줄에 `Recently: got 택배 상자 …; used 택배 상자 …` 도 있음.
- 원인: 상자를 열 때 속 물건을 `from: 'store'`, 지금 응답 키, 상자 값(`price`)째로 새로 넣음(`src/ui/homeshop.ts:624`) → `newlyBought`(`src/core/items.ts:929`, 1214)가 새로 산 것으로 잡음.
- 플레이어 증상: 본편이 연 턴에 다시 값을 치르는 장면을 쓰거나, 두 번 산 것처럼 다룰 수 있음(가짜 답으로 빈도 확정 불가). 상태창 잔고는 그대로라 숫자는 안 어긋남.
- 질문 4 와 같이 봐야 함(로어북 「여는 사람이 산 사람」).

## 문제 4 (사소) 가계부를 끈 채 상담원이 돈이 섞인 조건으로 `<deal/>` 하면 조건 전체를 버리고 아무 안내도 없음

- 누른 순서: 가계부 끔(`$st_col_wallet off`) → 편성 2 의 2부 전화 → 흥정 → 상담원 답 `money|100000` + `other|머리카락 한 줌` + `<deal/>` (단계22)
- 기대값: 돈 몫은 받을 수 없으니 남은 조건(머리카락 한 줌)이 조건 칸에 남거나, 주문이 안 된 까닭이 보임. 근거: 문제 1 과 같은 지침 문장. 다만 지침 OPERATOR_NO_MONEY 가 「terms never include money」라 모델이 어긴 답임.
- 실제값: 주문 안 됨, 조건 칸 「아직 없음」, 안내 없음. 상담원 말 「…주문 받았습니다.」는 통화·시청 기록에 남음.
- 원인: `src/ui/homeshop.ts:504` — 가계부가 꺼져 있고 `money > 0` 이면 조건을 통째로 `null`. 그 뒤 `value.deal && call.terms`(514) 가 거짓이라 말없이 지나감. 코드로만 본 같은 꼴: 수락 답에 `<terms>` 를 빼먹거나 `none` 이면 `parseOperator`(`src/core/homeshop.ts:797`)가 `deal:false, terms:null` 을 돌려 조건이 지워지고 말없이 끝남(이번엔 돌리지 않음).
- 플레이어 증상: 상담원이 받았다고 했는데 아무 일도 없고 조건 칸까지 비어 버림.

## 문제 5 (사소) 말로 받은 주문은 시청 기록에서 주문 줄이 수락하는 말보다 앞에 적힘

- 누른 순서: 1부 흥정 → 「네, 이십오만 원에 시연까지 할게요. 주문해 주세요.」 → 상담원 `<deal/>` (단계08, 단계09)
- 기대값: 시청 기록(본편 참고 기록)이 일어난 차례대로 — 내 수락 말 → 상담원 수락 말 → 주문 줄.
- 실제값: `user_order` 줄이 먼저, 그 뒤에 「주문해 주세요」·「주문 받았습니다」(단계09 MODULE_CONTEXT, `$hs_log` 상태08).
- 원인: `src/ui/homeshop.ts:506` 통화 말은 `saveLog`(333, `whenIdle().then(updateChat)` 로 한 박자 늦게) 로 적고, 바로 이어 520 `order()` 가 554 에서 `updateChat` 을 먼저 부름. 본편 응답을 기다리는 중이면 통화 말은 기다림이 풀릴 때까지 밀려 차이가 더 커짐.
- 플레이어 증상: 본편 모델이 「주문 → 수락 말」 순서로 읽음. 영향은 작음.

## 확인만 한 것 (문제 아님)

- 편성: 자동 호출 1회, 방송·진행자·시청자 절, 채널 머리, 로어북 「망상홈쇼핑」 본문이 감. 1부 원+시연·2부 시연만·3부 원만이 그대로 저장.
- 상점 문제 1(새로고침이 지금 진열을 피하지 않음): 망상홈쇼핑은 해당 없음. 새로 고침 요청의 피할 목록에 지난 편성 A·B·C 가 다 들어감(`showSource` 가 지금 편성 상품을 넣음, 단계19).
- 상점 문제 3(`$an_report` 자리표): 이번 실행은 진행 중 괴이·사건 칸 자체가 없어 재현 안 됨(실행마다 다름). 같은 함수를 쓰므로 같은 영향으로 봄.
- 채팅 반응: SAY 절, 지금 부, 방금 진행자 대사, 마지막 칸이 방금 쓴 채팅. 진실(숨은 원래 쓰임)은 안 감. 시청 기록에 진행자·시청자·내 채팅·반응이 다 적힘.
- 스티커: 떼면 드러난 글이 시청 기록에 한 번, 다시 열어도 거듭 적지 않음. 본편엔 드러난 조각만 감.
- 상담원 첫 말: 전화 걸 때 따로 1회, 말만 받는 꼴(조건·`<deal/>`·`<hangup/>` 없음), 통화와 시청 기록에 남음. 설정 「상담원 첫 말」 끄면 호출 없음.
- 흥정 요청: 흥정 절 + 출력 꼴 + `<deal/>` 절 + 끊음 켬 절, [통화] 끝이 방금 한 말, [지금 조건]이 지난 조건.
- 수락하는 말인데 `<deal/>` 이 없는 답: 주문 안 됨(지침대로), 조건·주문 단추 그대로.
- `<deal/>` 과 `<hangup/>` 을 같이 낸 답: 주문으로 처리(250,000원 빠짐, 상자 들어옴, 주문 1건 흥정·출연 1, 끊김 안 적힘, 끊음 줄 없음, 주문 뒤 말 호출 안 함). 지침 OPERATOR_HANGUP_ON 「A call that ends with the order taken ends with <deal/>」와 코드가 같은 뜻. 주문 뒤 창을 닫으면 「주문 완료」로 잠김.
- 상담원이 수락 전에 `<hangup/>`: 그 부에 끊김 저장, 끊김 화면, 주문 단추 없음, 숨은 단추로 hs-order 를 눌러도 주문 안 됨, 다시 걸어도 호출 없음, 시청 기록에 끊음 줄 한 번.
- 단추로 원 주문: 주문 뒤 말 따로 1회(ORDER 절, [지금 조건] 1,200,000원), 잔고 1,750,000 → 550,000, 완료 화면에 그 말. 설정 「주문 뒤 상담원 말」 끄면 호출 없음(시연 주문으로 확인).
- 지난 주문 넘김: 다음 부·다음 편성의 상담원 요청 [이 손님의 지난 주문]에 이름|치른 것|상태(미개봉 / 상자를 열어 받음, 시연 다녀옴)가 맞게 감. 지난 부의 통화는 안 섞임.
- 다음 턴 본편: 상자 도착(ARRIVE) 한 번·새로 산 상자 한 번, 그다음 턴엔 안 감, 상자는 목록에 남음. 시청 기록(주문 줄·상담원 말·스티커·내 채팅)은 다음 편성 전까지 매 턴 남음(설정 「넘기는 기간」 기본 0 = 계속 남는 기록).
- 상자 열기: 연 응답 키·시연 호출 턴(지금 턴+1) 적힘, 상자 빠지고 물건 들어옴. 다음 본편에 시연 호출(CALL)·방청(AUDIENCE) 각 한 번, 마지막 유저 메시지 바로 앞, 그다음 턴엔 안 감.
- 응답 실패(상담원): 창에 「상담원과 연결되지 않았어요」, 내 말은 통화에서 빠지고 입력칸에 돌아옴, 시청 기록에 안 남음. 첫 말 실패는 말없이 넘어감.
- 가계부 끔: 원 결제 단추 잠김, 흥정 요청에 OPERATOR_NO_MONEY 절, 돈 없는 조건 + `<deal/>` 은 주문(가계부 줄 없음).
- 주문한 턴 응답(c1) 다시 굴리기: 잔고 2,000,000 으로, 상자·ARRIVE 없음, 시청 기록의 주문 줄 빠짐, 본편 상태창 잔고 2000000.
- 설정 끔(`$hs_on 0`): 시연 호출·방청 블록과 시청 기록이 본편에서 빠짐.

## 사용자에게 물을 것

1. 플레이어가 「끊기」(창 닫기)를 눌렀다 다시 걸면 같은 통화가 이어지고(조건 남음, 첫 말 다시 안 부름), 상담원 요청 [통화]에는 끊었다 다시 건 흔적이 없습니다(단계13 기록). 이대로 두나요, 아니면 끊으면 조건을 버리고 새 통화로 하나요? (지침에 플레이어가 끊는 경우가 없음)
2. 주문한 턴의 응답을 다시 굴리면 주문·돈·상자는 없던 일이 되는데, 상담원이 「주문 받았습니다」라고 한 말과 시청 기록(방송·통화)은 그대로 남습니다(단계24). 통화 기록도 같이 되돌려야 하나요?
3. 망상홈쇼핑을 끈(`$hs_on 0`) 그 턴에도, 켜져 있을 때 넣은 주문의 상자 도착(ARRIVE)은 본편에 갑니다(단계25, `src/core/hslog.ts:163` hsBuyPasses 가 `$hs_on` 을 안 봄). 끄면 이것도 빼나요?
4. 상자를 여는 것을 「산 것」으로 다시 알려야 하나요(로어북: 여는 사람이 산 사람)? 아니면 주문한 턴에만 산 것으로 하고 연 턴은 「열었다」로만 하나요? (문제 2)
5. 「시연 다녀옴」은 호출 턴이 지나면 저절로 다녀온 것으로 칩니다(본편이 시연 장면을 실제로 썼는지와 상관없이, 단계21 요청). 이대로 괜찮나요?

## 가짜 답의 한계
