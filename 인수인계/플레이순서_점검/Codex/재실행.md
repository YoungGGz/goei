# 점검을 다시 실행하는 방법

이 브랜치를 체크아웃한 뒤 저장소 루트에서 실행한다. Node 24, Python 3, 전역 Playwright 및 Playwright가 실행할 수 있는 Chromium이 필요하다. 2026-11-22 점검에는 시스템 Chromium과 저장소의 테스트 호스트를 사용했다.

1. 저장소의 의존성과 카드 패키지를 준비한다. 이미 v0.21.32 자료가 준비된 작업본에서는 중복 빌드를 생략할 수 있다.

   ```sh
   npm ci
   npm run release:prep -- --skip-tests
   ```

2. 폰트 요청을 같은 글꼴로 재현하려면 별도 시험 도구 디렉터리를 쓸 수 있다. `AUDIT_FONTS`는 `ibm-plex-sans-kr`와 `jetbrains-mono` 디렉터리가 나란히 있는 위치다.

   ```sh
   npm install --prefix .scratch/audit-fonts @fontsource/ibm-plex-sans-kr @fontsource/jetbrains-mono
   export AUDIT_FONTS="$PWD/.scratch/audit-fonts/node_modules/@fontsource"
   ```

3. 기능별 폴더의 `run.mjs`를 실행한다. 예를 들어 포인트몰은 다음과 같다.

   ```sh
   node 인수인계/플레이순서_점검/Codex/03_백일몽_포인트몰/run.mjs
   ```

각 실행은 저장소의 `.scratch/play-audit-*`에 새 디렉터리를 만든다. 발견한 결함이 재현되는 케이스는 실패로 표시한다. 기능 실행기는 첫 실패 뒤에도 나머지 시나리오를 끝까지 실행한다. 이미 실행한 결과는 [실행기록.zip](실행기록.zip)에 들어 있다.

- `.log`와 `단위시험.txt`에서 세부 검사 이름·관찰값을 찾을 수 있다. AI 상담 원래 실행기가 출력한 1,034는 시도한 단언 수이며 마지막 실패 목록에 1개가 있다.
- `.jsonl`은 브라우저 페이지별 이벤트 순서다. `request`는 보조 모델 요청, `reply`는 시험 모델 응답, `main`은 본편에 넘긴 메시지, `state`는 호스트의 채팅 저장 내용이다. 저장하지 않는 화면 조작은 실행 로그와 캡처에 남는다.
- 상점의 Claude 재실행 기록에는 단계별 요청 전문과 상태 파일이 있다. 독립 실행은 PC·폰별 새로고침 전후를 포함한다. 두 몰 및 본편·이미지처럼 한 실행에서 함께 다룬 기능은 같은 원문을 각각 묶었다.
