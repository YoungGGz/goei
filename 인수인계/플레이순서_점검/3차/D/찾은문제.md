## 4. 리스AI 동작 (플러그인 탓 아님, 판정 밖)

- **플러그인이 보낸 본편(출동·임무 요청)은 리스AI 「중지」가 안 먹는다.** 리스AI 의 중지 단추는 입력칸으로 보낸 요청의 `abortController` 만 끊는데(`DefaultChatScreen.svelte` sendChatMain·abortChat), 플러그인 API `risuai.sendChat` 은 신호 없이 `processSendChat(-1, {})` 를 부른다(`plugins/apiV3/v3.svelte.ts:1461`). 그래서 임무 요청 뒤 중지를 눌러도 「만드는 중」이 그대로고(스트리밍 켬·끔 둘 다, D3b·D3e), 플러그인은 기다리는 중으로 보고 「요청 취소」를 대기만 지움으로 처리한다(D3b-1 NG 는 이 때문 — 잘못 봄). 늦게 온 답은 그대로 붙는다(D3b-2).
- 입력칸으로 보낸 요청은 중지가 먹고 리스아이가 쉬는 중으로 돌아온다(D3f-1).
- **답 오는 중 새 채팅(번호 밀기, E5a·E5b)**: 기다리는 중 새 채팅을 만들면(맨 앞에 끼워 번호 +1) 리스아이가 답을 보낼 때 잡은 번호 0, 곧 새 채팅에 써 넣는다. 원래 채팅으로 돌아가 있어도(E5b) 같다. 새 채팅은 상황판이 없어 플러그인이 답을 처리하지 않으므로 태그 줄(`[AN|…]`)이 글에 그대로 보인다. 원래 채팅은 내 말만 남고 상황판은 그대로. 플러그인은 답이 들어간 채팅 밖을 건드리지 않았다. 가르는 기준(단계 전에 적음): 답이 엉뚱한 채팅에 들어가는 것은 리스아이 동작. 근거 `out/run2-e5a-…357544`·`run2-e5b-…391877`.
- **E3-1 손으로 넣은 태그**: 연필로 `[AG|…]` 줄을 넣어도 플러그인은 다시 처리하지 않는다(처리 코드 없음, 코스 표 그대로). 상태창 칸은 E3-2 처럼 다음 요청에 화면대로 간다.
