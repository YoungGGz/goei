## 1. 저장 실패 (채팅 · 기기 저장소 · 카드)

| target | 걸리는 API | 비고 |
|---|---|---|
| `'chat'` | `risuai.setChatToIndex` | |
| `'storage'` | `risuai.pluginStorage.setItem` | `key` 로 열쇠 앞부분 거르기 (예: `'goei:prefs'`) |
| `'char'` | `risuai.setCharacterToIndex` | 카드 로어북·세계 기록 |

```js
import { setSaveFail, clearSaveFail, saveFails } from '../../../../tests/qc-host.mjs';
await setSaveFail(page, 'chat', { from: 2, count: 1, mode: 'throw' });   // 지금부터 2번째 호출 1회만 던짐
await setSaveFail(page, 'storage', { key: 'goei:prefs', mode: 'silent' }); // goei:prefs 쓰기를 끝까지 조용히 안 씀
await clearSaveFail(page, 'chat');   // target 없으면 전부 끔
await saveFails(page);               // [{ target, n, mode, key }] 걸린 기록
```

- `from`: setSaveFail 한 때부터 센 n번째(1부터). `count` 를 빼면 끝까지. `key` 가 있으면 맞는 열쇠만 센다.
- `mode: 'throw'`: `시험용 저장 실패(chat 2번째)` 예외.
- `mode: 'silent'`: 아무것도 안 쓰고 `undefined` 로 돌아온다. 실제 리스AI(996a553) `src/ts/plugins/apiV3/v3.svelte.ts` 를 읽고 맞췄다:
  - `setChatToIndex`·`setCharacterToIndex` 는 `withDbWrite` → `runWithPluginPermission(..., undefined)` 라 dbWrite 권한이 거절되면 `undefined` 로 조용히 돌아온다. 캐릭터 번호나 `chats[chatIndex]` 가 없을 때도 아무것도 안 쓰고 조용히 끝난다 (번호가 밀리거나 채팅이 지워진 경우).
  - `pluginStorage.setItem`(`process/pluginStorageStore.ts`)은 큰 값 쓰기에 실패하면 **던진다**. 조용히 안 쓰는 길은 이 판 리스AI 에서 찾지 못했다. `storage` 의 silent 는 「저장이 안 남는」 경우를 흉내 낸 것일 뿐 실제 리스AI 동작이라고 보지 않는다.
- 걸린 호출도 `__counts.setChat`·`__counts.setChar` 는 센다. `__calls.setChat` 에는 실제로 쓴 것만 쌓인다. 그래서 `startChat()`(setChat 이 쌓이길 기다림)은 채팅 저장이 실패하면 멈춘다. 실패를 켠 채 시작하려면 확인 스크립트 1-5 처럼 단추를 직접 누른다.
- 전역 방식: `window.__saveFail = { chat: { from, count, mode }, storage: {...}, char: {...} }`, 센 수 `window.__saveCalls`. 이미 있는 `__chatFail`(읽기 실패)·`__chatDelay` 와 같은 방식이다.

## 2. 기다림 붙잡기 (.loadmove / .button-icon-send)

`src/host/usebox.ts` `risuBusy()` 는 `.default-chat-screen` 안에서 `.loadmove` 가 있으면 busy, `.button-icon-send` 가 있으면 idle, 둘 다 없으면 unknown 으로 본다. 리스아이 `DefaultChatScreen.svelte` 는 만드는 중에는 `<button><div class="loadmove ...">`, 쉬는 중에는 `<button class="... button-icon-send">` 를 그린다. 스위치도 같은 자리에 같은 꼴로 넣는다.

```js
import { setRisuBusy } from '../../../../tests/qc-host.mjs';
await setRisuBusy(page, 'busy');  // .loadmove
await setRisuBusy(page, 'idle');  // .button-icon-send
await setRisuBusy(page, 'none');  // 둘 다 뺌 (unknown, 처음 상태)
```

- 「메인 응답 대기」(기본 3분)·「응답 다시 확인」(기본 30초)을 건너뛰려면 `boot(..., { clock: true })` 로 Playwright 가짜 시계를 깔고 `page.clock.fastForward(181_000)` 처럼 넘긴다. 시간 설정의 가장 작은 값이 1분·5초라 가짜 시계 없이는 오래 걸린다.
- 기다림은 `request(page, …)`(beforeRequest)를 부르면 켜진다. 「기다림 켜짐」을 밖에서 보는 법: 보내지 못한 직접 입력 하나만 있는 채팅(`core.setUnsent(글, true)`)이면 기다리는 중에는 진행 중 화면, 풀리면 시작 화면(`.gx-fac` 보임)이 열린다. 진행 중 화면에도 `.gx-start`(상황판 켜기)가 있으니 그것으로는 가르지 않는다.
- 확인한 것 (확인 스크립트 2-2·2-3):
  - busy 로 두고 창 열기 → 진행 중 유지. 창을 닫고 idle 로 바꿔 다시 열기 → 기다림이 풀려 시작 화면.
  - busy 로 두고 181초 넘김 → 그대로 진행 중. none 으로 바꾸고 31초 넘김 → 늦은 풀림, 열린 창이 시작 화면으로 다시 그려짐.

## 3. 보조 호출 스트리밍

`src/host/llm.ts` 는 `runLLMModel` 답이 `{ type: 'streaming', result: ReadableStream }` 이면 조각마다 글이면 그대로, 객체면 첫 값을 받고 마지막 것을 답으로 쓴다. 리스아이 `process/request/request.ts` 는 조각을 `{"0": 지금까지 누적 글}` 로 보낸다. 스위치도 같은 꼴로 보낸다.

```js
import { queueLlm, releaseStreams } from '../../../../tests/qc-host.mjs';
await queueLlm(page, '그냥 글 답');                              // { type: 'success', result }
await queueLlm(page, { stream: ['가나', '다라', '마'] });           // {"0":"가나"} → {"0":"가나다라"} → … → 닫힘
await queueLlm(page, { stream: ['A', 'B'], form: 'string' });     // 'A' → 'AB'
await queueLlm(page, { stream: ['하나', '둘', '셋'], stallAfter: 1 }); // 1조각 뒤 멈춤 (안 닫힘)
await releaseStreams(page);                                        // 멈춘 스트림을 마저 보내고 닫음 → 풀린 개수
await queueLlm(page, { stream: ['하나', '둘'], errorAfter: 1 });   // 1조각 뒤 끊김 (controller.error)
```

- 그 밖의 칸: `gapMs`(조각 사이, 기본 30ms). 이전처럼 `window.__llm` 에 `{ type, result }` 를 바로 넣어도 된다. `stream` 배열이 있는 칸만 스트림이 된다.
- 기록: `window.__calls.llm`(받은 요청), `window.__calls.llmStream`(스트림마다 `{ spec, sent, state: open|stalled|released|closed|error }`).
- 「모델 응답 대기」(기본 5분, 가장 작게 1분)가 지나 llm.ts 가 끊는 것까지 보려면 `clock: true` 와 `fastForward` 를 같이 쓴다.
- 확인한 것: 확인 스크립트 3-1~3-5 는 가짜 `runLLMModel` 을 직접 불러 llm.ts `readStream` 과 같은 방식으로 읽었다. **플러그인 기능(괴담넷·위키 등)이 이 스트림을 받아 처리하는 길은 이 스크립트에서 돌리지 않았다.** 구간 스레드가 그 기능에서 확인한다.

## 4. 조립 단계 실패 (`__goeiFaultSteps`)

- 주입 블록(`GOEI_TEST:` 이름표, src/body.ts `faultOn`)은 `scripts/build.mjs` 가 배포 본체 `dist/goei-body.js` 에서 빼고 시험 본체 `dist-test/goei-body.js` 에만 남긴다. 확인함: dist 에는 `__goeiFaultSteps` 글자가 없고 dist-test 에는 있다.
- 틀에서 켜는 법:
  ```js
  import { boot, testBodyCode, request } from '../../../../tests/qc-host.mjs';
  const { page, logs } = await boot(browser, fixture, chat, { fixtureDir, body: testBodyCode });
  await page.evaluate(() => { globalThis.__goeiFaultSteps = ['주인공']; });  // 여러 개도 됨
  await request(page, messages);  // 로그: [goei] 요청 조립 실패: 단계 주인공(시험용 예외 주입) — …
  await page.evaluate(() => { globalThis.__goeiFaultSteps = []; });
  ```
- 단계 이름은 src/body.ts 의 `step()`·`stepAsync()` 이름 그대로다(`grep -oE "step(Async)?\('[^']+'" src/body.ts` 로 뽑음). 그리고 `'beforeRequest'` 를 넣으면 조립 전체가 던진다.
  기록 태그 정리, 더한 글, 로어, 리롤 되감기, 망상홈쇼핑, 명부 다듬기, 사용 상자, 상태창, 상태창 모양, 소지품, 시드, 시드 채팅 읽기, 시작 카드 표식, 신분, 에셋 출력 읽기, 옛 이미지 태그, 유저 이름, 이미지 지침, 인물 기록, 주인공, 지시문 채팅 읽기, 지시문·전화 풀기, 진행 계획, 참고 기록, 채팅 읽기, 호출 기록.
  (조립 순서 안의 단계도 있고 응답 처리 쪽 단계도 섞여 있다. 어느 함수 안인지는 쓰기 전에 src/body.ts 에서 본다. 확인 스크립트에서 실제로 돌린 것은 「주인공」 하나뿐이다.)
- 코스의 「로어·주인공·상태창·소지품·인물 기록·시드」는 모두 이 목록에 있다.
- T1 은 dist-test 본체를 쓴다. T2(실제 리스AI)에는 release 본체가 들어가므로 이 주입이 안 된다.
