## 2. 틀

### 2-1. T1 가짜 리스 (빠른 갈래, 요청 글 검사)
- `npm run release:prep` 이 만드는 판 그대로의 카드·본체·자료 팩을 `tests/qc-host.mjs`·`tests/qc-settings-harness.mjs` 에 넣는다.
- 기록 자리: 보조 호출 `risuai.runLLMModel`(첨부 처리 뒤 실제 입력), 본편 `beforeRequest` 훅이 돌려준 메시지, `output` 처리 뒤 저장된 채팅.
- **답을 돌려주기 전에 요청 글부터 검사**한다 (가짜 답이 빠진 정보를 덮지 않게).
- 더하는 스위치 (시험 도구만 고침, src 는 안 건드림):
  - 저장 실패: `setChatToIndex`(채팅), `pluginStorage.setItem`(`goei:prefs` 등), `setCharacterToIndex`(카드 로어북·세계 기록). 꼴 둘 — 예외 던지기 / 실제 리스AI 처럼 조용히 안 쓰기.
  - 기다림 붙잡기: 가짜 화면에 리스AI 의 `.loadmove`(만드는 중)·`.button-icon-send`(쉬는 중)를 넣었다 뺐다 해서 「메인 응답 대기」(기본 3분) 뒤 판정과 바로 풀림까지 돈다.
  - 보조 호출 스트리밍: 가짜 `runLLMModel` 이 조각으로 돌려주기·조각 받다 멈추기 (실제 리스AI 는 보조 호출을 늘 스트리밍 끈 채 보내서 T2 로는 이 길에 못 닿는다).
- 조립 단계 실패: 시험 본체의 `__goeiFaultSteps` 로 로어·주인공·상태창·소지품·인물 기록·시드 단계를 하나씩 실패시킨다.

### 2-2. T2 실제 리스AI + 가짜 모델 서버 (공통 갈래)
- 리스AI 원본을 받아 `pnpm install` 뒤 띄운다. 옛 틀(`/mnt/project-files/작업_1121/…/틀/`)은 옛 저장소 주소만 돌리고 11-21 판 상태 파일이라 그대로 쓰지 않는다. `tools/risu-real/shots.mjs`(모듈 import 로 설치·설정 넣기)를 바탕으로 새로 짠다. 받는 주소는 `ygberserk/goei/release` 와 리스AI `/proxy2` 길 둘 다 이 판 `release/` 로 돌린다.
- 모델 길 (리스AI 소스로 확인한 제약):
  - 웹 리스AI 는 스트리밍 끈 요청을 `localhost`·`127.0.0.1`·`0.0.0.0` 으로 보내면 거절한다(globalApi.svelte.ts:709·845). 보조 호출은 늘 스트리밍 끔이라, **리스AI Node 서버로 띄우거나**, 막히지 않는 주소(컨테이너 IP 등)에 `usePlainFetch` 켬 + CORS 응답으로 가짜 서버를 둔다. 0단계에서 둘 중 되는 쪽을 정한다.
  - 본편은 `reverse_proxy`(`forceReplaceUrl`), 보조는 `xcustom:::` 모델(다른 주소)로 둬서 가짜 서버가 **본편과 보조를 주소로 가린다** (reverse_proxy 주소는 하나뿐이라 둘 다 두면 못 가림).
  - 보조 호출은 리스AI 쪽 취소 신호가 없어, 플러그인이 시간 제한으로 다시 보내면 같은 요청이 두 번 온다. 대본은 순서가 아니라 **요청 내용으로 고른다**.
  - 비스트리밍 답에 `reasoning_content` 를 주면 리스AI가 본문 앞에 `<Thoughts>` 를 붙인다. 생각 블록 대본은 이 꼴과 본문 속 태그 꼴 둘 다.
- 가짜 서버는 들어온 요청 전문을 순서대로 적고, 대본 답을 돌려준다. 늦게 답하기로 「답 오는 중」을 만들고, 429·5xx·빈 답·형식 틀린 답도 준다.
- 리스AI는 저장을 0.5초 모아서 한다. 새로고침 갈래는 「리스AI 저장 끝난 뒤」와 「일부러 바로」를 나눈다.
- 모델 키는 없다. 값이 자연스러운지·실제 모델이 얼마나 어기는지는 이 점검으로 정하지 않는다 (2-4).

### 2-3. T3 화면 판독
- 실제 리스AI에서 PC 1280, 폰 344×882(폴드 접힘·손가락), 폰 가로, 폴드 펼침 752×749(기기 배율 1.8).
- 폴드 펼침은 플러그인 설정 「펼친 폴드 화면 배치」(PC/모바일)·「배율」(기본 70%)·「창 가로·세로」(기본 95%)를 기본값과 끝값으로 바꿔 본다.
- 실기(갤럭시 Z 폴드8)가 아니라 크기를 흉내 낸 것이다. 결과에 그렇게 한 줄 적는다.

### 2-4. 가짜 답으로 정할 수 있는 것과 없는 것
- 정할 수 있음: 요청 글에 정보가 빠지거나 넣지 말 것이 들어감, 지침과 처리 코드가 다른 표식·꼴을 씀, 답을 잘못 받음, 상태·화면·다음 턴이 어긋남, 되돌리기 누락.
- 가짜 답 세 꼴: 지침대로 쓴 답 / 조금 어긋난 답(표식 빠짐·꼴 틀림·생각 블록 안 표식·없는 이름·0원 값) / 실패(빈 답·오류·늦음·멈춤).
- 정할 수 없음: 값의 자연스러움, 실제 모델의 지침 위반 빈도. 사실로 한 줄만 적고 버그의 이유로 쓰지 않는다.

### 3-1. 미리 넣을 사용자 결정 (기대값을 바꾸는 것)
- 첫 요청: 상황판 NEW 줄(무작위 괴이·사건·요원)은 첫 턴에 들어가는 것이 정상. 상점·몰 요청 [진행 중 괴이·사건] 칸의 발생대기 NEW 줄이 자리표째 가는 것도 「그대로 둠」(11-22 21:51).
- 첫 장면: 새 채팅은 평소 하루에서 연다. 이면의 주민들 개인 첫 장면 13편은 뺐다(빈 칸이 정상, 직접 입력·커스텀 임무만). 첫 장면 글은 Claude 가 쓰지도 고치자고 하지도 않는다. 민간인 첫 장면 로어북 두 줄은 빈 채로 사용자 몫, 민간인 시작은 연락처가 빈 것이 정상. 프리랜서 직접 입력·커스텀 임무 기본 로어는 특수재난대응협회·중림 지하상가. 채팅 중 커스텀 임무는 지금 장면을 끊지 않고 이어 간다. 답 길이·끊는 자리·주인공 대리 금지는 프리셋 몫이라 지침에 없는 것이 정상.
- 아바타: 남·여 고르는 창, 기본 Persona Female A, 성별은 본편에 안 보냄. 기존 인물로 시작하면 그 인물로 잠김.
- 잔고: 상점·몰·홈쇼핑 상담원·포인트몰 상담원 요청엔 숨김. 괴담넷·괴담톡·위키에 섞여 가는 것은 숨김 대상 아님(재검토 판정).
- 끄기: 소지품을 끄면 「다음 메시지에 사용」을 비우고 상점 방문을 닫음. 가계부를 끄면 그때부터 잔고 칸만 빠짐. 상점은 소지품·가계부 중 하나만 꺼져도 꺼지고 스위치 잠김. 다시 켠 첫 턴 [Inventory] 에 「그 사이 변화는 없음」 한 줄. 홈쇼핑을 꺼도 도착 글은 남음.
- 먼저 끊는 장치: 홈쇼핑 통화 끊음(그 상품 전화 주문 막힘, 같은 부면 조건 남음), 1:1 상담 끊음(다시 열면 다른 상담사), 우주몰 문의 끊음(구매는 됨, 쇼핑몰 새로고침으로만 풀림, 그 전 대화는 남음).
- 몰: 우주몰·포인트몰 자동 호출 기본 「수동」. 포인트몰은 백일몽 소속일 때만, 정가 포인트만, 몰이 포인트를 주지 않음. 망상홈쇼핑은 카드 「접속하기」로 여는 단독 창(탭·주소줄 없음). 전화 창이 열린 동안 방송이 흐르지 않음.
- 소지품: 모든 물건에 무게, 넘어도 얻기를 막지 않고 색만 진해짐, 본편엔 넘었는지·얼마나만. 소지 한도 기본 25kg, 인물은 명부 carry. 요원증 「들기」는 그냥 둠. This turn·Recently 겹침 정리는 산 물건만(합침·잃음 두 번은 결정과 맞음).
- 인물 기록: 「사장」·동물 별명은 초상 태그·소속 같은 다른 근거가 있을 때만 첫 등록. 성적 기록 기능은 Claude 가 손대지 않음(점검에서도 뺌).
- 설정: 바꾸면 바로 저장, 확인 칩·팝업 없음(기다리는 중 바로 저장 자체는 설계). 숫자는 −/+ 와 직접 입력.
- 화면: PC 와 폰 배치는 일부러 다름(폰은 작동 자체를 다르게, 폰 쓸기는 창 전체 기록). 화면은 승인 시안 기준. 폴드 펼침은 PC 화면을 통째 줄인 것. 메뉴 접기(11-22): 쓸어 접기 폐기, 접는 단추는 ‹ › 사이 가운데·같은 색, 접으면 구분선 위로, 설정 밑에 닫기, 퇴짜 놓은 모양 목록. 유령 단추 자리는 메모리끼리 갈리니 결정표에서 코드로 먼저 확정.
- 알고 넘긴 한계: 응답 둘 이상 연달아 지우면 상황판은 마지막 하나만 되돌아감(v0.21.34).

## 4. 코스 (한 판 플레이 순서)

한 채팅을 처음부터 끝까지 이어 간다. 구간마다 **대표 줄기**(T2, 실제 단추)를 먼저 돌고, 그 구간의 **갈래**(T1, 상태만 바꿔)를 돈다. 단계마다 실행 전에 기대값과 결정표 줄을 적고 `run.mjs` 가 자동 대조한다.

각 단계에서 보는 것 다섯: ① 모델에게 가는 요청 글 전문 ② 받은 답 처리 ③ 저장 상태(`chat.scriptstate`, `chat.goeiPeopleV1`, `chat.localLore`, 카드 로어북, `pluginStorage`) ④ 화면(채팅 속 그림 포함) ⑤ **다음 턴 본편 요청**. 그리고 구간마다 「게임으로 말이 되나·로어북과 맞나」를 본다.

### A. 설치·첫 실행
1. 권한 묻기(replacer·mainDom·sendChat): 다 허락 / 하나씩 거부 (mainDom 거부면 유령 단추 없이 감시만 도는 길).
2. 카드 가져오기 → 본체 받기. 갈래: 정상 / 40초 넘김 / 조각 4개 동시 받기 중 일부 실패 / 받기 목록이 설치된 플러그인보다 새 판(플러그인 업데이트 안내가 맞는지) / 「파일로 넣기」 / 실패 뒤 1분 안 다시 받기.
3. 세계 자료 받기 실패 → 받기 창 → 다시 받기 → 다시 시작.
4. 「설치·업데이트」 창: 한 번에 넣기(로어북·인사말 → 사진 → 아이콘 → 위키 기본 문서 → 토크나이저, 중간 실패해도 다음으로, 위키·사진 받기 중간 실패), 정식 카드 아이콘 판정, 아이콘 거절·되돌리기, 봇 이름 바꾸기, **다른 봇에 설치하는 길**(0.21.34 고침).
5. 업데이트: 확인 → 준비 → 적용 / 건너뛰기 / 준비 뒤 다른 캐릭터로 바꿔 적용 / 리스AI 플러그인 탭 업데이트(`//@update-url`).
6. **옛 판 채팅을 업데이트 뒤 이어 하기**: 빠진 설정 변수 채우기, 명부의 새 세력에 맞춘 태그·세력 변수, 상태 점검의 「카드가 낡음/플러그인이 낡음」 줄.
7. **다른 봇(괴이 아닌 카드)**: 그 채팅에서 요청·응답·그리기에 손대지 않는지, 본체 받는 중 첫 요청, 다른 봇에 다녀온 직후 판정 전 그리기.
8. 말이 되나: 카드 로어북·인사말·에셋이 판과 맞는지, 위키 기본 문서가 카드 위키와 같은지.

### B. 시작 패널 → 첫 장면
1. (세계 › 시작 화면 꾸미기에서 칸 순서·켜고 끄기·묶음·칸마다 첫 장면을 바꾼 갈래는 K 에서 하고, 여기선 바뀐 대로 나오는지만 본다.)
2. 시작 전 「새 채팅 기본 설정」(시작 전 범위는 기본값만), 시작 전 AI 상담.
3. 소속×시작 방식 표를 다 돈다: 특수재난관리국·백일몽·이면의 주민들(묶음, 인물만)·프리랜서·민간인 × 인물 장면·직접 입력·커스텀 임무 × 한국어·영어, 그리고 **캐릭터(요원)로 플레이**. 대표 줄기 넷(관리국 장면, 백일몽 직접 입력, 프리랜서 커스텀 임무, 요원으로 플레이), 나머지는 T1.
4. 아바타, 시작 잔고, 출발.
5. 직접 입력: 전송 → 막히면 채팅 속 「전송 대기·취소」 실제 클릭 → 기다리는 중 취소는 두 번. 2차 06 남은 4건(기다리는 틈, 비스트리밍·첫 글자 전) 실제 리스AI로.
6. 첫 장면 힌트 「첫 행동」과 「재선택」, 새로고침 뒤 다시 붙는지.
7. **첫 요청 글**: 시드(order 399), 시작 로어북(설정 세계 › 조직 › 기본 세력 기록 › 「첫 장면에 함께 넣을 로어북」), 상황판 NEW 줄, 잔고 칸, 요원으로 플레이할 때 시드·주인공 자리·명단. 두 번째 전송부터 시드가 빠지는지.
8. **새로고침 뒤 창을 열지 않고 바로 보내기**: 유저 이름({{user}})·상태창 지침·명부가 비는 길.
9. 말이 되나: 첫 장면·지시문(OPENING)이 「평소 하루에서」 방향과 맞는지, 장면 글·호칭·장소가 명부에 있는지.

### C. 평소 턴 (본편 조립과 응답 처리)
1. 요청 조립 전문: 로어 덩어리(RP지침 → Tag → Faction → Roster → 세력 → 시드 → 특수 → 괴이 → 요원) → 주인공 → 참고 기록(게시판·톡·위키·홈쇼핑, 「본편 반영 총 상한」으로 나눔) → 상태창 블록 → [Inventory] → 망상홈쇼핑 → 인물 블록·Router·Director → 이미지 지침(끝, 프리필 앞).
2. 참고 기록 여러 개가 한꺼번에 찰 때 상한 나누기.
3. 본편 로어북: 「로어북 보내기」(플러그인이 고름/리스AI 직접), 세력 요약·요원 명단 끄기, 검색 깊이·토큰 예산. 설정 「로어북 확인」 화면 목록 = 실제 요청인지. 입력 처리기에서 고르는 길과 응답 뒤 고르는 길(다시 굴리기·자동 전송)이 같은 결과인지.
4. 응답 처리 순서: 상황판 태그 → 해금 → 가계부·포인트 맞추기 → 사용 정리 → 상점 정리 → 맞춤 주문 완성 → 빠진 변수 채우기 → 다음 턴 로어 미리 고르기 → 인물 기록 → 보조 이미지 태그 → 인터넷 자동 호출.
5. **생각 블록**: 본편 응답(`<Thoughts>`·`<think>`·`<thinking>`, 여는/닫는 태그 하나 빠짐, `reasoning_content`, 스트리밍 켬/끔)에서 상황판 태그·상태창 줄·가계부 맞추기(`findStatusTags`)·상점 표식(0.21.34 고친 `findShopTag`)·홈쇼핑 접속·이미지 태그·인물 기록이 각각 생각 글을 읽는지. 보조 호출 응답의 생각 글 걷기.
6. **본편 요청 실패·리스AI 자동 재시도**: 이미 조립한 요청을 그대로 다시 보내는 길에서 참고 기록·인물 기록·상점 「이번 턴」이 두 번 끼는지, 진행 창 턴, 「사용」 잠금.
7. 조립 단계 하나 실패(T1 주입) → 그 단계만 빠지고 표식은 지워져 나가는지. 응답 처리 첫 저장 실패 → 그 턴 뒤 처리가 통째로 빠지는 자리.
8. 보조 기능을 「메인 모델」로 둔 호출이 리스AI beforeRequest 를 지날 때 본편 로어·참고 기록이 안 붙는지(지문 판정).
9. Router·Director 성공 길과 시간 제한(넘긴 뒤 늦은 답 버림).
10. 말이 되나: 매 턴 켜지는 Roster·괴이·요원 로어가 장면의 인물·장소와 맞는지(흔한 낱말 이름 로어 빠짐 같은 것).

### D. 상황판·지도·출동·임무
1. 지도: 지역 → 장소 → 사건, 걸러 보기, 확대(두 손가락·끌기·Ctrl+휠, 다시 그린 뒤 확대 유지). 괴이·사건 카드 그림(낱말로 고르는 공용 그림, 엉뚱한 그림이 안 붙는지).
2. 편성(요원·지원) → 출동: 다음 본편 user 칸 지시문(COMMON + OPENING/CONTINUATION + CONTEXT), 지난 지시문은 CONTEXT 만.
3. 커스텀 임무 보내기·취소(카드째 물림/대기만 지움). 응답을 지운 뒤 임무 창에서 건 요청이 되돌아간 상태에 남는지(0.21.34).
4. 사건 진행 → 손으로 종료(두 번) → 일지·보고서. 손으로 끝낸 괴이를 모델이 다시 적는 경우, 요원 사망과 그 되돌림.
5. 요원 정보 → 괴담톡·위키·인물로.
6. 명부: 이름·순서 바꾸기 → 다음 턴 요청·연락처·지도.
7. 갈래: 답 오는 중 출동·종료·명부 저장 / 리스AI 「중지」·실패로 답 없이 끝난 뒤 임무 요청·다시 고르기·요청 취소가 막히지 않는지(0.21.34) / 메시지를 다 지우고 같은 채팅에서 다시 시작·상황판 껐다 켜기 → 옛 기준 상태 비움(0.21.34) / 「발생 후보」 끔 / 덧붙일 규칙에 `[[…]]` 가 든 채 출동.
8. 진행 창: 머리글 끌기·접기, 폰 점 막대 끌기, 채팅 옮긴 뒤·새로고침 뒤. 0.21.34 고친 넷(Router·Director 시간 제한이 실패로 보임, 앞 턴 위키·몰 호출이 새 턴에 안 섞임, AI 상담 토큰이 「보조 지난 턴」에 안 더해짐, 단추만 써도 「인터넷」 점이 안 켜짐), 수동 「새 응답 읽기」 여러 묶음.
9. 말이 되나: 지시문의 장소·괴이·요원이 명부와 맞는지, 지난 사건 되풀이가 없는지.

### E. 장면 속 가게 (상점)
1. 본편 답 `[shop: 가게|주인]` → 채팅 속 카드 → 열기 → 진열 요청 글(잔고 숨김).
2. 사기 / 문의·흥정 / 특가 / 돈 아닌 대가 / 팔기(대가로 산 물건 포함) / `<deal/>` / 쫓겨남.
3. 다음 턴: [Inventory] This turn·just bought 한 번만, 답이 본편 넘어간 뒤 오면 다음 본편에(앞 요청 실패해 다시 보낼 때 두 번 실리는 길).
4. 다 사고 새로고침 → 피할 목록.
5. 판단자 셋: 메인 / 갱신기 / 자동.
6. 포인트 가게: 백일몽 소속일 때만. 비소속으로 열기·팔기.
7. 상점 설정: 고유 상점·시그니처 상품 표, 희귀·특가 구획, 값 기준, 다양성, 맥락 반영, 상점 생각 단계, 상품 수 → 진열 요청 글이 바뀌는지.
8. 갈래: 다시 굴리기 / ◀▶ 오가기 / 다른 채팅 다녀오기 / 새로고침 뒤 답 없는 내 말 / 저장 실패 / 상점 끔 / 소지품·가계부 끔.
9. 말이 되나: 가게·주인이 로어북에 있고, 값이 그 가게가 받는 대가로 나가는지.

### F. 폰
1. **괴담톡**: 연락처 → 1:1 손 보내기 → 자동 확인(수동·창 열 때·매 턴) → 선톡·초대 확률과 쉬는 턴 → 단톡 만들기·초대 → 공지·세력 공지 → 보기 전용 방(사전설정 셋, 자동 호출, 이어 보기) → 전화(본편이 이어 씀) → 연락처 추가·삭제(삭제면 1:1 기록까지) → 선물(1:1 만) → 저장 길이 한도·「초대받은 단톡방 정리」(0.21.34 기본값 고침).
2. **괴담넷·괴담갤·세정게·연어마켓**: 목록 → 글 열기·추천·스크랩 → 글쓰기(연어마켓 거래 구분) → 댓글·답글 → 새 댓글 보기 → 쪽지·선쪽지 확률·쉬는 턴·자동 정리 상한 → 지우기(두 번) → 닉네임(브라우저 로그인·게시판 안, 비우면 익명, 페르소나 이름 기본값) → 참조 칩 6개. 0.21.34 고침: 남의 글에 댓글 단 뒤 게시판 목록 새로 받기 → 출처 글이 빠져도 선쪽지가 남는지.
3. **사진 표식**: 모델이 글·댓글·쪽지·톡에 쓴 `[사진:이름]`·`[사진:이름_표정]` → 에셋 그림.
4. **첨부**: 실제 사진(고르기·붙여넣기·끌어놓기) / 가상 사진·영상·파일·링크(최대 3) → 보조 요청엔 사진, 본편엔 설명 글만. 사진을 저장소에서 못 읽으면 「n번 사진을 못 읽음」 줄.
5. **괴이위키**: 찾기 → 없으면 작성 → 링크 따라가기(부모 원본) → 다시 쓰기 → 지우기 → 자동 작성(끔/창 열 때/매 턴) → 「컨텍스트에 포함」 → 다음 턴. Director 위키 칸. 다른 채팅에서 실패 안내 안 뜸(0.21.34).
6. **인터넷 브라우저**: 탭 열기·닫기·되살리기, 앞뒤, 폰 탭 목록·홈, 폰 주소창 ↻, 쓸기와 메뉴 뒤로, PC 마우스 제스처, 1.5초 안에 채팅 바꾸기. 0.21.34 고침: 채팅 카드로 단독 창을 연 뒤 뒤로 가기(탭 쌓임), 단독 창 안 뒤로, 왼쪽 메뉴 뒤로와 주소줄 ‹ ›, 뒤로 간 탭 새로고침(최근 10칸 밖), 보던 게시판 즐겨찾기 → 목록.
7. **묶음 호출(Joint)**: 게시판·괴담톡이 같은 모델·매 턴일 때 한 요청, 말버릇 칸 떼기.
8. 갈래: 다른 채팅 다녀오기 / 작업 중 새로고침 / 다시 굴리기(턴 열쇠만 보는 설계) / 중간 응답 지우기 뒤 「이번 턴 쓴 글」 기한 / 각각 끔 / 메인·보조 모델 / 생각 단계·비망록·생성 언어.
9. 말이 되나: 게시판 글·톡 상대·세력 이름이 명부에 있는지, 연락처 탭이 로어북 탭 설정과 맞는지.

## 6. 판정 규칙

1. 어긋난 단계마다: 기대값, 결정표 줄(출처 표시 포함), 실제값, 요청 글·상태 파일 경로.
2. 결정표 대조 → 사용자 결정이면 「의도」로 뺀다. Claude 판정·위키 근거로만 뺀 것은 결과에 그 출처를 붙인다.
3. **두 관점 재확인**: (가) 재현 — 다른 점검자가 같은 순서로 다시 돌려 같은 결과, 실제 리스AI에서도 생기나(T1 에서만 나면 틀 탓인지, 리스AI 자체 동작인지 가른다) (나) 설계 — 그 코드가 게임에서 무슨 역할인지, 고치면 무엇이 같이 바뀌는지, 사용자 결정과 부딪히지 않는지. 둘 다 진짜일 때만 「진짜 버그」.
4. 분류 다섯: 진짜 버그 / 의도 / 잘못 봄 / 결정됨·안 만듦(다시 묻지 않음) / 물을 것(설정·세계관·기능을 넣고 빼는 것만). 내부 동작 세부는 Claude 가 일관된 쪽으로 정할 거리로 적고 묻지 않는다. 시키지 않은 UI 는 「넣을까요」로 묻지 않는다.
5. 「실제 모델로는 확인 안 함」은 사실 한 줄로만.
6. 고치지 않는다.
7. 결과 파일은 GPT 교차점검용(근거 경로·요청 전문 포함)과 사용자 보고용(결론 한 줄 + 화면에서 겪는 일, 파일·줄 나열 없음, 시각 KST)을 나눈다.

- data-action 아닌 조작: 채팅 속 클릭(상태창 말풍선·위키 이름·요청 취소·상점 카드·맞춤 주문 카드·전송 대기 표), 지도 확대, 진행 창 끌기, 메뉴 끌기·쓸기, 스티커 끌기.
- 지침 파일 23개 중 요청 글에서 실제로 쓰인 것을 확인한 것.
- 공통 갈래 표 칸 중 돈 것.
- 끝내 못 돌린 것은 결과 맨 끝에 까닭과 함께 짧게 둔다. **남은 일로 올리지 않는다.** 이 틀로 원래 못 하는 것(실기 폴드, 실제 모델)만 있어야 하고, 그 밖의 칸이 남으면 점검이 끝난 것이 아니다.
