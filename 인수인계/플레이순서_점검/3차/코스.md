# 플레이 순서 전수점검 3차 · 코스 (초안)

- 판: v0.21.34 (main 9312894). 점검은 이 판 하나로만 한다. 중간에 고친 코드가 들어오면 그 판을 새로 적고 바뀐 곳에 닿는 구간만 다시 돈다.
- 이 글은 **점검 방법과 순서**다. 여기 적은 「볼 곳」은 코드를 읽어 짚은 자리일 뿐, 버그라고 확인한 것이 아니다. 버그 판정은 돌려 본 뒤 6장 규칙으로만 한다.
- 실행은 사용자가 「해」 한 뒤.

## 2. 틀

### 2-1. T1 가짜 리스 (빠른 갈래)
- `npm run release:prep` 이 만드는 판 그대로의 카드·본체·자료 팩을 `tests/qc-host.mjs`·`tests/qc-settings-harness.mjs` 에 넣는다 (2차와 같음).
- 기록 자리 세 곳 고정: 보조 호출 `risuai.runLLMModel`(첨부 처리 뒤 실제 입력), 본편 `beforeRequest` 훅(돌아온 메시지 전문), `output` 처리 뒤 저장된 채팅.
- **답을 돌려주기 전에 요청 글부터 검사**한다 (가짜 답이 빠진 정보를 덮지 않게).
- 더하는 것: `updateChat` 의 n번째 호출을 실패시키는 스위치, 본편 「기다리는 중」을 원하는 만큼 붙잡아 두는 스위치.

### 2-2. T2 실제 리스AI + 가짜 모델 서버 (공통 갈래)
- 리스AI 원본(kwaroran/RisuAI)을 띄우고 `tools/risu-real/` 과 조종 서버(`/mnt/project-files/작업_1121/폴드펼침_고침/실제리수_752/틀/`)로 조종한다.
- 리스AI 설정의 모델을 `reverse_proxy` 로 두고 주소(`forceReplaceUrl`)를 컨테이너 안 OpenAI 호환 가짜 서버로 돌린다 (리스AI 소스 `src/ts/process/request/request.ts:468` 에서 이 길 확인). 보조 모델(submodel)도 같은 서버로 돌려, 플러그인 보조 호출(`runLLMModel` → `requestChatDataMain`)까지 받는다.
- 가짜 서버는 들어온 요청 전문을 순서대로 적고, 대본(구간마다 미리 쓴 답)을 돌려준다. 답을 일부러 늦게 주는 기능으로 「답 오는 중」 틈을 만든다. 스트리밍 켬/끔 둘 다.
- **0단계에서 먼저 확인**: 본편·보조 둘 다 이 서버로 오는지, 늦게 주기가 리스AI 「기다리는 중」으로 보이는지. 안 되는 갈래가 있으면 T1 로 흉내 내고 결과에 「T1 흉내」라고 적는다.
- 모델 키는 없다. 그래서 값의 자연스러움·지침을 얼마나 어기는지는 이 점검으로 정하지 않는다 (2-4).

### 2-3. T3 화면 판독
- 실제 리스AI 에서 PC 1280, 폰 344×882(폴드 접힘·손가락), 폴드 펼침 **752×749 배율 1.8**.
- 「눌러 보는 전수점검」 도구(`tools/click-audit/`)는 마지막에 빠진 단추 세기에만 쓴다.

### 2-4. 가짜 답으로 정할 수 있는 것과 없는 것
- 정할 수 있음: 요청 글에 정보가 빠지거나 넣지 말 것이 들어감, 지침과 처리 코드가 다른 표식·꼴을 씀, 답을 잘못 받음, 상태·화면·다음 턴이 어긋남, 되돌리기 누락.
- 가짜 답은 **세 가지 꼴**로 준다: 지침대로 쓴 답 / 조금 어긋난 답(표식 빠짐·꼴 틀림·생각 블록 안에 표식·없는 이름) / 실패(빈 답·오류·늦음).
- 정할 수 없음: 값이 자연스러운지, 실제 모델이 얼마나 자주 어기는지. 결과에 사실로 한 줄만 적는다.

## 3. 시작 전에 만드는 결정표

`3차/결정표.md` 를 먼저 만든다. 모든 기대값과 발견은 이 표에 대조한다.

- 사용자 결정: 프로젝트 메모리(MEMORY.md 와 연결된 파일), 두 저장소 CLAUDE.md, 1·2차 기록에 적힌 사용자 답(시각 포함).
- 2차 ④ 「걸러 낸 것」 32건(의도 25·잘못 봄 7)과 재확인에서 빠진 것.
- 지침 글(`지침/*.txt`)과 위키·명부(`카드/wiki-base.json`, 명부 로어북). 위키도 Claude 가 쓴 글이 섞였으니, 위키만 근거인 기대값은 「위키 근거」라고 따로 표시한다.
- 근거가 없는 기대값은 정하지 않는다. 내부 동작 세부(되돌리기·판정 같은 것)는 일관된 쪽으로 Claude 가 정하고, **설정·세계관·기능을 넣고 빼는 것만** 「물을 것」으로 남긴다.

## 4. 코스 (한 판 플레이 순서)

한 채팅을 처음부터 끝까지 이어서 간다. 구간마다 **대표 줄기**(T2, 실제 단추)를 먼저 돌고, 그 구간의 **갈래**(T1, 상태만 바꿔)를 돈다. 단계마다 실행 전에 기대값과 근거를 적고 `run.mjs` 가 자동 대조한다.

각 단계에서 보는 것 넷: ① 모델에게 가는 요청 글 전문 ② 받은 답 처리 ③ 저장 상태(`chat.scriptstate`, `chat.goeiPeopleV1`, `chat.localLore`, 기기 저장소 `goei:prefs`) ④ 화면과 **다음 턴 본편 요청**.

### A. 설치·첫 실행
1. 카드 가져오기 → 플러그인 켬 → 본체 받기. 갈래: 정상 / 40초 넘김 / 중간에 끊김 / 「파일로 넣기」 / 실패 뒤 1분 안 다시 받기.
2. 자료 팩(세계 자료) 받기 실패 → 받기 창 → 다시 받기 → 다시 시작.
3. 「설치·업데이트」 창: 한 번에 넣기(로어북·인사말 → 사진 → 아이콘 → 위키 기본 문서 → 토크나이저, 중간 단계 실패해도 다음으로), 아이콘 거절·되돌리기, 봇 이름 바꾸기.
4. 업데이트: 확인 → 준비 → 적용(사진 다 받은 뒤 카드 합치기) / 건너뛰기. 2차 17-2·17-3(업데이트 단추) 고친 곳 다시.
5. 볼 것: 카드 로어북·인사말·에셋이 판과 맞는지, 위키 기본 문서가 카드 위키와 같은지.

### B. 시작 패널 → 첫 장면
1. 시작 전에 「새 채팅 기본 설정」 열고 몇 개 바꿈 (시작 전 범위는 기본값만 되는 것이 맞는지).
2. 소속×시작 방식 표를 다 돈다: 특수재난관리국·백일몽·이면의 주민들(묶음, 인물만)·프리랜서·민간인 × 인물 장면·직접 입력·커스텀 임무 × 한국어·영어. 대표 줄기는 셋(관리국 장면, 백일몽 직접 입력, 프리랜서 커스텀 임무), 나머지는 T1.
3. 아바타 고르기, 시작 잔고, 출발.
4. 직접 입력: 전송 → 막히면 「전송 대기·취소」 → 기다리는 중 취소는 두 번. 2차 06 남은 4건(기다리는 틈) 다시.
5. 첫 장면 힌트 「첫 행동」 카드와 「재선택」, 새로고침 뒤 다시 붙는지.
6. **첫 요청 글**: 시드(order 399)·시작 로어북(설정 세계 › 조직 › 기본 세력 기록 › 「첫 장면에 함께 넣을 로어북」, 결정표에 사용자 결정 있음)·상황판 NEW 줄(첫 턴에 들어가는 것이 정상, 사용자 11-22)·잔고 칸. 두 번째 전송부터 시드가 빠지는지.
7. 로어북 대조: 장면 글·호칭·장소가 명부·위키에 있는 것인지.

### C. 평소 턴 (본편 조립과 응답 처리)
매 턴 공통이라 여기서 한 번 깊게 본다.
1. 요청 조립 순서 전문 확인: 로어 덩어리(RP지침 → Tag → Faction → Roster → 세력 → 시드 → 특수 → 괴이 → 요원) → 주인공 → 참고 기록(게시판·톡·위키·홈쇼핑, 「본편 반영 총 상한」으로 나눔) → 상태창 블록 → [Inventory] → 망상홈쇼핑 → 인물 블록·Router·Director → 이미지 지침(끝, 프리필 앞).
2. 참고 기록 여러 개가 한꺼번에 찰 때 상한이 어떻게 나뉘는지 (2차 07 못 돌림).
3. 응답 처리 순서: 상황판 태그 → 해금 → 가계부·포인트 맞추기 → 사용 정리 → 상점 정리 → 맞춤 주문 완성 → … → 인물 기록 → 보조 이미지 태그 → 인터넷 자동 호출.
4. **생각 블록 응답** (`<Thoughts>`·`<think>`): 상황판 태그·상태창 줄·가계부 맞추기·상점 표식·홈쇼핑 접속·이미지 태그·인물 기록이 각각 생각 블록 안 글을 읽는지. 2차 99 결함 1(상점)은 고쳐진 자리(`findShopTag`)를 다시 보고, 나머지(`findStatusTags` 등)는 처음 본다.
5. 첫 저장이 실패하면 그 턴 뒤 처리가 통째로 빠지는 길(body.ts 응답 처리) — T1 저장 실패로 돌려 화면·다음 턴에 무엇이 남는지.
6. Router·Director 성공 길 (2차 07 못 돌림).

### D. 상황판·지도·출동·임무
1. 지도: 지역 → 장소 → 사건 고르기, 걸러 보기.
2. 편성(요원·지원) → 출동: 다음 본편 user 칸에 지시문(이동_임무_지시문.txt COMMON + OPENING/CONTINUATION + CONTEXT). 지난 지시문은 CONTEXT 만 남는지.
3. 커스텀 임무 보내기·취소(카드째 물림 / 대기만 지움).
4. 사건 진행 몇 턴 → 손으로 종료(두 번) → 일지·보고서·되감기 기준.
5. 요원 정보 → 괴담톡·위키·인물로 건너가기.
6. 명부: 이름·순서 바꾸기 → 저장 → 다음 턴 요청과 연락처·지도에 반영되는지.
7. 갈래: 답 오는 중 출동·종료·명부 저장 / 「발생 후보」 끔 / 상황판 끔 / 덧붙일 규칙에 `[[…]]` 가 든 채 출동(코드상 Directive 오류 길, 돌려서 확인).
8. 진행 창: 채팅 옮긴 뒤·새로고침 뒤 (2차 14 못 돌림).
9. 게임으로 말이 되나: 출동 지시문의 장소·괴이·요원 이름이 명부와 맞는지, 지난 사건이 되풀이되지 않는지.

### E. 장면 속 가게 (상점)
1. 본편 답에 `[shop: 가게|주인]` → 카드 → 열기 → 진열 호출 요청 글.
2. 사기 / 문의·흥정 / 특가 / 돈 아닌 대가 / 팔기(대가로 산 물건 포함) / `<deal/>` / 쫓겨남.
3. 다음 턴: [Inventory] This turn·just bought 가 한 번만 가는지, 답이 본편 넘어간 뒤 오면 다음 본편에 실리는지(`w` 표시, 앞 요청이 실패해 다시 보낼 때 두 번 실리는 길 포함).
4. 다 사고 새로고침 → 피할 목록.
5. 판단자 세 갈래: 메인 / 갱신기 / 자동(갱신기가 매 턴 돌 때만 갱신기).
6. 포인트 가게: 백일몽 소속일 때만. 비소속으로 열기·팔기.
7. 갈래: 다시 굴리기(산 것·판 것 돌아옴, 쫓겨남은 안 돌아오는 자리 — 결정표 대조) / 다른 채팅 다녀오기 / 새로고침 뒤 답 없는 내 말 / 저장 실패 / 상점 끔 / 소지품·가계부 끔.

### F. 폰
1. **괴담톡**: 연락처 → 1:1 보내기(손, 바로 저장) → 자동 확인(매 턴·창 열 때, 답 오는 중 기다림) → 단톡 만들기·초대 → 공지 → 보기 전용 방 → 전화(본편이 이어 씀) → 연락처 추가·삭제(삭제하면 1:1 기록까지) → 선물(1:1 만).
2. **괴담넷·괴담갤·세정게·연어마켓**: 목록 → 글 열기·추천·스크랩 → 글쓰기(연어마켓 거래 구분) → 댓글·답글 → 새 댓글 보기 → 쪽지 → 지우기(두 번) → 닉네임 바꾸기(브라우저 로그인·게시판 안 둘 다, 비우면 익명) → 참조 칩 6개.
3. **첨부**: 실제 사진(고르기·붙여넣기·끌어놓기) / 가상 사진·영상·파일·링크(최대 3) → 보조 요청엔 사진, 본편엔 설명 글만 가는지.

## 5. 공통 갈래 표 (모든 구간에 건다)

구간마다 아래 열 둘을 한 번씩. 칸마다 기대값과 근거를 적고, 처리 코드가 없는 칸은 「처리 없음 — 돌려서 무엇이 보이는지」로 돈다.

## 6. 판정 규칙

1. 어긋난 단계마다: 기대값, 근거(결정표 줄), 실제값, 요청 글·상태 파일 경로.
2. 결정표 대조 → 의도·사용자 결정이면 「의도」로 바로 뺀다.
3. **두 관점 재확인**: (가) 재현 관점 — 다른 사람이 같은 순서로 다시 돌려 같은 결과가 나오나, 실제 리스AI 에서도 생기나(T1 에서만 나면 틀 탓인지 본다) (나) 설계 관점 — 그 코드가 게임에서 무슨 역할인지, 고치면 무엇이 같이 바뀌는지, 사용자 결정과 부딪히지 않는지. 둘 다 진짜일 때만 「진짜 버그」.
4. 분류는 넷: 진짜 버그 / 의도 / 잘못 봄 / 물을 것(설정·세계관·기능을 넣고 빼는 것만).
5. 「실제 모델로는 확인 안 함」은 사실 한 줄로만. 버그의 이유로 쓰지 않는다.
6. 고치지 않는다. 목록만 보여 주고 사용자가 정한다.
