## 문제 1 (중대) 새로고침할 때 지금 진열대에 걸린 물건을 「다시 내지 말 것」에 넣지 않음

- 누른 순서: 열기(진열 A·B) → 아무것도 안 사고 새로고침. (또는 C 가 걸린 채로 다시 열고 새로고침)
- 기대값: 새로고침 요청이 지금 걸린 A·B 를 피하라고 알림. 근거: 지침 VARIETY 「Do not repeat items from the previous shelf」, 설정 「지난 진열대 피하기」, 오늘 사용자 지적(새로고침하면 같은 물건).
- 실제값: 피할 목록 절이 **아예 없음**(단계13). C 가 걸린 채 새로고침하면 목록에 A·B 만 있고 C 는 없음(단계08). 새로고침 요청에는 지금 진열대도 안 들어감. 모델이 같은 것을 내면 그대로 다시 진열됨(단계13 둘째 검사).
- 원인: 피할 목록 = 지난 목록(`prev`) + 산 것(`src/core/shop.ts:1074` prevNames). 지금 진열대의 안 팔린 물건은 새 진열을 받은 **뒤에야** `prev` 에 들어감(`applyShelf`, `shop.ts:828`). 그래서 늘 한 판 늦다. 새 진열을 받을 때 지금 것과 같은 이름을 거르지도 않음(`applyShelf` 의 `withIds(base, r.items, [], ...)`).
- 플레이어 증상: 마음에 안 들어 새로고침했는데 같은 물건이 또 나옴. 오늘 고친 「다 사고 새로고침」과 같은 종류인데, 안 사고 새로고침하는 길은 그대로 남아 있음.
- 같은 함수를 쓰는 곳: 우주 쇼핑몰·포인트몰·망상홈쇼핑 편성도 `SHELF_RULES` 로 같은 목록을 씀 → 2·3·4 점검에서 확인.

## 문제 2 (보통) 상점 모델에 잔고를 안 보내기로 했는데 [최근 본문]에 잔고가 그대로 감

- 기대값: 잔고(1000)가 상점 요청에 없음. 근거: `src/ui/shop.ts:374` 주석·설정 「넘기는 것·남는 것」(11-08 전수점검: 잔고 칸이 그대로 갔다), 지침 COMMON 「Never mention the player's money」.
- 실제값: [상태창] 칸에서는 잔고를 뺐지만, [최근 본문]에 본편 응답 원문이 그대로 들어가 마지막 줄 `[▣|…|관리국/신입|1000]` 가 같이 감(단계02). 원문의 `[shop: 이정 책방|]` 표식도 같이 감.
- 원인: 최근 본문(`src/core/refs.ts:265` recentTurns → storyText)이 상태창 줄을 거르지 않음.
- 플레이어 증상: 주인이 주인공 형편을 아는 듯 값을 부를 수 있음(가짜 답으로는 빈도 확정 불가).
- 같은 함수를 쓰는 곳: 쇼핑몰·망상홈쇼핑(`shopSource` 공용), 괴담넷·괴담톡·위키도 `recentTurns` 를 씀 — 그쪽이 잔고를 받아도 되는지는 사용자 결정 필요(질문 1).

## 문제 3 (보통) [진행 중 괴이·사건] 칸에 본편용 지시 줄이 자리표째 감

- 기대값: 지금 진행 중인 괴이·사건이 읽을 수 있는 글로 들어감.
- 실제값: `NEW [AN|전라남도 순천시|욕망의 방|활성|<등급>|<배치>|<상황>]` 처럼 본편 모델에게 「채워 써라」고 주는 줄이 `<등급>` 같은 빈 자리표째 감(단계02, 실행마다 지역은 다름).
- 원인: `src/ui/shop.ts:376` 이 `$an_report`·`$in_report`(본편 로어북 🏷️Tag 에 넣는 브리핑, `src/core/world/output.ts`) 를 그대로 붙임.
- 플레이어 증상: 상점 모델이 쓸모없는 자리표를 받고, 「NEW」 지시를 자기 일로 읽을 수 있음. 정보는 거의 없음.
- 같은 함수를 쓰는 곳: 쇼핑몰·망상홈쇼핑·포인트몰 1:1 상담(`src/ui/malls.ts:637`).

## 문제 4 (사소) 물건 줄에서 칸 하나가 빠지면 칸이 밀린 채 받아 설명이 사라짐

- 누른 순서: 첫 진열에서 무게 칸이 빠진 7칸 줄을 받음(이번 점검 첫 실행에서 가짜 답을 잘못 써서 우연히 겪음).
- 기대값: 꼴이 틀린 줄은 버리거나 다시 묻기.
- 실제값: 설명이 무게 칸으로 들어가 숫자가 아니라 버려지고, 소지품에 설명 없이 들어감(본편 요청에 `- 누런 부적지 묶음 (부적을 쓰면 값이 덜 든다)` 로만 감).
- 원인: `parseLine`(`src/core/shop.ts:652`)이 칸 수를 보지 않음.

## 확인만 한 것 (문제 아님)

- 다 사고 바로 새로고침 / 다음 턴에 다시 들어와 새로고침: 피할 목록에 산 A·B 가 있음(오늘 고친 것 유지).
- 구매: 잔고 1000→500, 거래 2건(기준 응답 c1), 소지품 2개, 빈 진열대 안내.
- 다음 턴 본편: 구매 사건·주인과 나눈 말이 한 번, 그다음 턴엔 사건이 다시 안 나오고 소지품 목록엔 남음.
- 팔기: 산 값·남은 횟수·지난번 부른 값이 요청에 들어가고, 말로 수락(`<deal/>`)하면 판매 처리(잔고 500→750), 다음 턴 판 사건 한 번.
- 산 턴 응답을 다시 굴리면 잔고 1000 으로 돌아오고 진열대에 A·B 가 다시 보임.
- 표식 없는 응답이 오면 상점 상태를 비움.
