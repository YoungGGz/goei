- 실제값: `out/단계11_PC_납기지남_완성표식_문의요청.txt:362` `[shop-ready: cos|안 꺼지는 손전등]` 이 [최근 본문] 안에. 본편 요청(단계13)에는 안 샘 — sanitize 는 본편에만 걸림.

## 문제 2 (보통, 재현) 운영자가 「~ 이름|값」으로 값을 바꾸면 그 값으로 팔림 — 지침은 「값은 고정」

- 누른 순서: 진열 → 질문 「우산 너무 비싸요 깎아 주세요」 → 답 `<change mode="partial">~ 말 듣는 우산|100000</change>` → 우산 장바구니 → 입금.
- 기대값: 값 바꾸는 줄은 안 받음, 2,200,000 그대로. 근거: 같은 요청의 지침 COMMON 「Prices are fixed: the 운영자 never haggles, never lowers a price」, TALK_OUTPUT 「Prices are fixed, so never change one」(`지침/우주쇼핑몰.txt:4,123`), 설정 「문의로 물건 바꾸기」 끔일 때 TALK_NO_STOCK 「no "~" lines」.
- 실제값: 저장 `{price:100000, orig:2200000}`, 잔고 10,000,000 → 9,900,000 으로 삼(단계21, `out/상태21.json`).
- 원인: `src/core/shop.ts:786` 이 `~` 줄을 읽고 `:879` applyTalk 가 몰에서도 그대로 적용. 우주몰에서 막는 곳 없음.
- 플레이어 증상: 흥정하면 운영자 모델이 지침을 어길 때 90% 넘게 깎인 값으로 살 수 있음(모델이 어기는 빈도는 실제 모델로 안 봄, 받아들이는 쪽이 느슨한 것은 확정).

## 문제 3 (보통, 재현) 값 칸이 현물(「기억 한 조각」)인 상품이 0원 「송금」으로 공짜에 들어옴 + 같은 요청의 지침 두 절이 값 칸을 다르게 말함

- 누른 순서: 상품 가져오기 → 답에 `기억 저금통|기억 한 조각|…` → 장바구니(합계 ₩0) → 주문 하기 → 입금 한다.
- 기대값: 원 정수 값이 아닌 줄은 진열에서 버리거나 살 수 없음. 근거: 지침 COMMON 「Buying is a bank transfer in Korean won」「Prices are Korean won as plain integers」「the cheapest item costs about a million won」. 포인트몰은 같은 경우를 버리게 1차(Codex 05)에서 고침(`src/core/shop.ts:719` pointShelf).
- 실제값: 저장 `{price:0, pay:"기억 한 조각"}`, 장바구니 ₩0, 입금 뒤 잔고 그대로 9,900,000 인데 소지품에 들어옴. 본편엔 `기억 저금통 (paid with bank transfer to 우주 쇼핑몰 + 기억 한 조각)`(단계22, `out/단계22_…_본편.txt`). 진열 요청엔 COMMON(원 정수만)과 SHELF 「if this shop is not paid in money … write its own payment in short Korean words instead」가 같이 실림(`out/단계22_갈래_진열_현물값_공짜.txt`).
- 원인: SHELF 절은 상점과 같은 글(`지침/우주쇼핑몰.txt:8`). `src/ui/malls.ts:314` 의 「값 0 이하 안 삼」은 포인트몰(`p`)에만.
- 플레이어 증상: 상품이 0원으로 떠 공짜로 받고, 본편은 「송금 + 기억 한 조각」을 치른 것으로 이야기함(실제로 깎인 것은 없음).

## 문제 4 (보통, 재현) 답을 기다리는 중 페이지를 새로고침하면 답 없는 내 말이 대화에 남고 본편에도 감

- 누른 순서: 문의 창에서 「우산은 어때?」 전송 → 답 오기 전 페이지 새로고침(저장된 채팅으로 다시 띄움) → 다시 문의 창 → 다음 본편.
- 기대값: 답을 못 받은 내 말은 실패 때처럼 대화에서 빠지거나 다시 보낼 수 있게. 근거: 같은 함수의 실패 처리 `src/ui/malls.ts:229-243`(답이 안 오면 내 말을 지우고 입력칸에 돌려줌), 지침 4절 「페이지 새로고침 — 저장 상태만으로 이어지나」.
- 실제값: 대화 끝 `me:우산은 어때?`(답 없음), 「입력하는 중」은 사라져 다시 보내면 같은 말이 두 줄. 본편엔 `… / protagonist: "우산은 어때?"` 로 운영자 답 없이 감(단계27, `out/단계27_…_본편.txt`, `out/상태27.json`).
- 원인: `src/ui/malls.ts:626` 이 보내기 전에 내 말을 저장하고, 되돌림은 응답 실패(catch) 때만.
- 플레이어 증상: 창을 다시 열면 운영자가 대답 안 한 질문이 남아 있고, 본편 모델이 운영자 답을 지어낼 수 있음.

## 문제 5 (사소, 재현) 운영자 답이 오기 전에 본편이 한 턴 넘어가면 그 답은 본편에 영영 안 감

- 누른 순서: 「신문 내용 미리 알려 줄 수 있어?」 전송 → 답 오기 전 본편 전송(u2)·응답(c2) → 그다음 답 도착 → 다음 본편(u3).
- 기대값: 운영자 답이 어느 본편에든 한 번 감. 근거: 지침 3-C 「사건은 그 턴 본편에 한 번」, 4절 「늦게 온 답」.
- 실제값: u2 요청엔 내 질문만(`protagonist: "신문 내용 …"`, 답 없음), 늦게 온 답은 `k:c1` 로 적혀 u3 요청에 없음(단계28 `_본편1`·`_본편2`, 줄 기준 `owner:c1:못 알려 준다`).
- 원인: `src/ui/malls.ts:622`·`:197` 이 보낼 때의 마지막 응답 키를 적고, `src/core/malls.ts:262` mallEvents 는 지금 마지막 응답 키와 같은 줄만 넘김.
- 플레이어 증상: 운영자가 한 말(거절·쪽지 제안 등)을 본편이 모름. 실제 Risu 에서 몰 창 답을 기다리는 동안 본편 전송이 막히는지는 확인 안 함(몰 호출은 플러그인 보조 호출이라 막을 근거 못 찾음).

## 문제 7 (사소, 재현) 같은 턴에 사서 바로 운영자에게 판 물건은 본편에 「판 일」만 가고 「산 일」·도착이 빠짐

- 누른 순서: 우산 입금 → 같은 창에서 우산을 팔고 `<deal/>` 로 판매 → 다음 본편.
- 기대값: 구매 사건과 판매 사건이 각 한 번. 근거: 지침 3-C 「사건(샀다·팔았다)은 그 턴 본편에 한 번」.
- 실제값: `This turn: just sold 말 듣는 우산 to 우주 쇼핑몰 …` 만, just bought·ARRIVE 없음(단계25 `_본편`).
- 원인: `src/core/items.ts:960` boughtPassing 이 살아 있는(안 판) 물건만 봄.
- 플레이어 증상: 본편은 주인공이 갖지도 않은 우산을 팔았다고 읽음. 잔고·소지품 상태는 맞음.

## 물을 것 (기대값 근거 없음)

1. 설정 진열 개수 2~2 인데 답이 3개면 3개가 다 진열됨(단계29, `src/core/shop.ts` applyShelf 는 「진열대 물건 수」 상한만 자름). 개수를 넘는 줄을 자를지.
2. 운영자 문의가 끊긴(`<closed/>`) 뒤 진열을 새로 받기 전까지는 다음 턴에도 계속 끊긴 채이고, 자동 호출 「수동」에서는 주소창 새로고침으로 진열을 새로 받으면 바로 풀림(단계23). 코드 주석(`src/core/malls.ts:59`)의 설계로 보이나 사용자 날짜 결정은 못 찾음.

## 확인만 한 것 (문제 아님)

- 화면 단추 경로(PC·폰): 진열·질문(상품 붙음)·쪽지 구매·견적·선납·장바구니·입금·주문 조회·받기·팔기 모두 동작. 폰 가로 넘침 없음, 문의 창이 화면 안.
- 「입금 한다」 연타: 한 번만 빠짐(잔고 2,800,000, 거래 4건, 소지품 각 1줄), 안내가 실패 문구로 안 덮임.
- 잔고·진실이 운영자·진열 요청에 안 감. 쓰는 턴에만 Really 줄. 사건은 한 번, 그다음 턴엔 안 나옴.
- 새로고침 피할 목록에 산 것 + 지금 걸린 신문(1차 고침 유지).
- 받은 턴(c3) 다시 굴리기: 손전등 죽고 주문은 「완성」으로, 새 응답에 표식 다시 붙음, 그 턴 판매도 되돌아감. 산 뒤 응답(c2) 지우고 다시 보내기: 사건 한 번씩. 산 턴(c1) 다시 굴리기 뒤 다시 사기: 돈 한 번.
- 문의 빈 답: 내 말 되돌림·입력칸·붙인 상품 돌아옴(호출 3회). 꼴 틀린 답 뒤 재시도 성공: 호출 2회, 대화 2줄. 진열 꼴 틀림: 안내, 진열·진열 턴·장바구니 그대로.
- 문의 끊음 켬: closed, 입력 꺼짐, 정가 구매는 됨, 본편에 끊은 대화 한 번. 끔: KICK_OFF, 답의 `<closed/>` 무시.
- 팔기: `<offer>none</offer>` → 「우리는 사지 않는다」, 판매 단추 없음. 말로 수락 `<deal/>` → 판매. 산·판 턴 다시 굴리기 → 둘 다 없던 일, 우산 다시 진열.
- 창 닫은 채 답 도착: 저장됨.
- 설정: 메인 모델 → mode model, exactly N, TRUTH_NONE, 배정 끔, PLAIN, VARIETY 끔, 지난 목록 피하기 끔(AVOID_PREV 없음), 맥락 반영 끔(상태창·본문·괴이 칸 없음), 컨텍스트 포함 끔(본편에 몰 사건 없음, 목록엔 물건), 문의로 물건 바꾸기 끔(TALK_NO_STOCK, 더하기 무시), 완성 알림 끔(표식·READY 없음, 받기 단추는 있음).
- 자동 호출 매 턴: 본 진열이 있으면 새 응답에 1회, 같은 턴 다시 굴리기엔 안 부름, 안 본 진열이면 다음 턴에 안 받음(사용자 11-15).

## 못 돌린 것

- 실제 Risu 에서 몰 답을 기다리는 동안 본편 전송·다시 굴리기가 되는지(문제 5 의 빈도). 가짜 호스트만.
- 다른 채팅 갔다 오기: 가짜 호스트는 채팅 번호가 늘 0 이라 「다른 채팅」을 못 만듦.
- 실제 모델 답(왈도체, 운영자가 진실을 흘리는지, 값이 등급에 맞는지)은 안 봄.
