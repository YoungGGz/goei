- 재현 커밋: `807f994` (0.21.33 + 포인트몰 지침 고침). 시험 카드는 `.scratch/fixture/` 에 있는 것을 그대로 썼다. 다시 빌드하지 않았다.
- 돌리는 법: 이 폴더에서 `node run.mjs a1|a2|b|c|d|e|f`. 인자를 빼면 a1~e 를 차례로 돌린다. 한 번에 브라우저 하나, headless chromium.
- 가짜 Risu: `tests/qc-settings-harness.mjs`. 모델 답은 모두 가짜(`window.__llm`)이고, 실제 API 는 부르지 않았다.
- 처음 설정 (`lib.mjs startedChat`):
  - 시작한 채팅, 두 말풍선.
  - 상태창 `[▣|2025.03.14|11:20 PM|🌙|6°C|관리국 본부|없음|없음|없음|관리국/신입|1000]`.
  - 소속은 관리국(A00), 가계부 시작 잔고 1000.
  - 자료 팩은 소지품·모습을 넣었다. 기기 설정(prefs)은 처음에 비어 있다.
- 저장 자리:
  - 채팅 설정: `chat.scriptstate` (`$gen_*`, `$ph_*`, `$sh_*`, `$it_*` …).
  - 기기 값: 플러그인 저장소 `goei:prefs`. 기본 설정·세계·테마, 기본값(`vars`), 고친 지침(`guides`), 시간이 여기 있다.
- 결과 파일: `out/<파트>_단계NN_*.txt` (요청 글·누른 조작별 바뀐 값), `out/<파트>_상태NN.json`, `out/결과_<파트>.json`, `out/log_<파트>.txt`.
- 돌린 단계는 57개, 자동 대조로 46개가 통과했다. 이 중 a2 의 11~13 세 단계는 「바꾼 값」 목록에 상태 변수가 섞여 실패로 나왔다. 상태 변수는 `$st_item_use*`, `$st_shop`, `$it_resumed`, `$st_col_log` 이고, 이걸 손으로 빼면 통과다. 그래서 실제 통과는 49개다.

잘 되는 것 (확인함):
- 모든 설정 페이지의 조작은 누르면 바로 저장된다. 한 조작이 채팅과 기기를 같이 바꾸는 일은 없다.
- 기본값 저장·불러오기·초기화는 점검 → 저장·불러오기 한 곳에만 있다.
- 지침 23개의 기본 글은 지침/ 파일과 글자까지 같다. 편집 화면에서 절로 나눴다 합쳐도 글이 바뀌지 않는다. 고치면 바로 저장되고, 고친 FIRST 절이 첫 진열 요청에 들어간다. 초기화하면 원래 글로 돌아오고 머리에 「기본값」이 뜬다.
- 로어북 호출 페이지:
  - 세력 요약과 요원 명단을 끄면 본편 요청에서 빠진다.
  - 상시 로어북을 고르면 상점 요청에 들어간다.
  - 최근 거래 줄 수를 3으로 하면 본편에 그 줄이 들어간다.
- 상점 요청:
  - 기능 표 「진열 챗로그 1턴」과 생성 공통 「유저 메시지 빼기」「영어」가 요청 글에 반영된다.
  - 상점 모델을 메인으로 하면 메인으로 부른다.
  - 형식 오류 재시도 3, 재시도 모델 보조로 하면 4회 부르고, 첫 번째만 메인이다.
  - 모델 오류 재시도 0이면 1회, 기본값이면 3회 부른다.
- 수 칸: 관제 페이지 밖의 모든 칸은 + 한 번에 1씩(상한이 1만 이상이면 100씩) 오르고, 범위 밖 수를 넣으면 끝값으로 맞춰지며, 칸에 보이는 값이 저장값과 같다.

## 문제

### 문제1 — 괴담톡 「초대받은 단톡방 정리」가 기본값 저장·불러오기·초기화에서 빠진다 (실제로 돌려 재현)

- 누른 순서:
  1. 설정 → 괴담톡을 연다.
  2. 「초대받은 단톡방 정리」를 켜고 수를 바꾼다.
  3. 점검 → 저장·불러오기에서 「기본값으로 저장」을 누른다.
  4. 변수를 비우고 「불러오기」를 누른다.
  5. 「초기화」를 누른다.
- 기대값과 근거: 같은 페이지의 DM·단톡·공지 정리처럼 기본값에 담기고, 불러오기로 돌아오고, 초기화로 지워져야 한다. 근거는 사용자 11-08 「저장·불러오기·초기화는 점검 한 곳」과, 설정 값이 기본값의 대상이라는 것.
- 실제값:
  - `$ph_storage_auto_invited`, `$ph_storage_limit_invited` 가 `prefs.vars` 에 안 들어간다. 불러오기로 돌아오지 않고, 초기화 뒤에도 남는다.
  - 새 채팅도 이 값을 받지 않는다. 새 채팅은 `prefs.vars` 를 받기 때문이다 (src/ui/app.ts:1504).
  - 기록: `out/a1_단계11_기본값으로_저장.txt`, `a1_단계12_비우고_불러오기.txt`, `a1_단계13_초기화.txt`, `a1_상태10~13.json`.
- 증상: 플레이어가 이 정리 설정을 기본값으로 저장해도 새 채팅마다 다시 꺼져 있다. 초기화해도 이 값만 남는다.
- 근거:
  - src/core/settings.ts:196 `PREF_VAR` 에는 `storage_(auto|limit)_(dm|group|notice)` 만 있고 `invited` 가 없다.
  - 설정 칸은 src/core/setdef/phone.ts:6 `keep('dm'|'group'|'notice'|'invited')` 와 :104 에서 만든다.

### 문제2 — 관제 페이지 수 칸에 범위 밖 수를 치면, 저장은 끝값인데 칸에는 친 수가 그대로 남는다 (실제로 돌려 재현)

- 누른 순서:
  1. 설정 → 관제(호출 흐름)를 연다.
  2. 「형식 오류 재시도」 칸에 1003 을 치고 Enter, Tab 을 누른다.
  3. 「자동 다시 연결」 칸에 -5, 「다시 보기」 칸에 1002 를 같은 식으로 넣는다.
- 기대값과 근거:
  - 칸이 끝값으로 바뀌어야 한다. 「형식 오류 재시도」 3, 「자동 다시 연결」 0, 「다시 보기」 2.
  - 근거는 사용자 11-19 「모든 칸 직접 입력」 결정과 다른 페이지들의 동작이다. 다른 페이지는 같은 입력에서 칸이 끝값으로 바뀐다 (파트 b, 모든 다른 페이지 통과).
- 실제값:
  - 저장값은 `$gen_retries=3`, `$hs_retry=0`, `$gen_reiterate=2` 로 맞다.
  - 칸에는 「1003」「-5」「1002」가 그대로 남는다. 다른 페이지에 갔다 오면 그제서야 끝값이 보인다.
  - 기록: `out/f_단계01~03_*.txt`, `out/결과_f.json`, `b_단계19_수칸_모음.txt`.
- 증상: 플레이어는 재시도 1003회가 들어간 줄로 보게 된다. 실제로는 3회다.
- 근거:
  - src/ui/editor/flowpage.ts:71 은 칸 값을 그릴 때만 넣는다.
  - src/ui/app.ts:982 `fl-do` 는 원래 처리기만 부르고, 관제 페이지를 다시 그리지 않는 것으로 보인다. 왜 다시 그리지 않는지까지는 읽지 않았다.

### 문제3 — 지침 편집 화면에서, 비우면 기본 글이 쓰이는 절 18개에 「비우면 기본 글이 쓰여요」가 안 붙는다 (core 함수를 실제로 돌려 재현)

- 누른 순서:
  1. 설정 → 지침 → 예를 들어 Router 를 연다.
  2. ROLE 절을 비운다.
  3. 편집 화면 표시를 본다.
  4. 그 절이 요청에 어떻게 들어가는지 본다.
- 기대값과 근거: 비우면 기본 글이 쓰이는 절에는 표시가 붙어야 한다. 근거는 전수검사 11-13 나-51 사용자 결정 「표시 = 실제로 기본 글을 쓰는 절」과, src/core/guides.ts 의 `blankUsesDefault` 주석.
- 실제값:
  - 비운 뒤 `guideSec` 은 null 이고, `guideTxt` 는 기본 글을 돌려준다. Router ROLE, Hs ORDERS_NONE, Phone MAIN_CONTEXT.VIEWS, Bm PICKUP_TRY 를 core 번들로 돌려 확인했다.
  - 그런데 `blankUsesDefault` 는 false 라서 표시가 안 붙는다.
  - 해당 절: Hs ORDERS_OPENED·ORDERS_BOX_GONE·ORDERS_SEALED·ORDERS_LINE·ORDERS_AND·HEAD_ORDERS·ORDERS_NONE, Bm PICKUP_TRY·PICKUP_WAIT, Director FACTS·SCENE, Router ROLE·RULES, Phone ANNOUNCEMENTS·MAIN_CONTEXT.VIEWS·MAIN_CONTEXT.HABITS, Cos·Bm BOUGHT_LINE.
  - 목록은 `out/c_단계02_빈칸표시_대조.txt` 에 있다.
- 증상: 플레이어는 절을 비우면 그 글이 요청에서 빠진다고 알게 된다. 실제로는 기본 글이 그대로 간다.
- 근거:
  - src/core/guides.ts:219 `BLANK_DEFAULT_MOVED`, :236 `blankUsesDefault`, :250 `guideTxt`.
  - 읽는 자리: src/core/homeshop.ts:743, src/core/items.ts:1024, src/core/people/director.ts:86-87, src/core/people/router.ts:42, src/core/phone.ts:956·1207, src/core/shop.ts:1164.
  - Phone ANNOUNCEMENTS 는 src/core/phonePrompt.ts:99 에서 절 통째로도 쓴다. 그래서 둘이 섞여 있다.

## 물을 것

- 해당 칸:
  - 화면 「창 바깥 불투명도」 0~100, 5씩 (src/ui/settings.ts:127)
  - 그림 크기와 접힌 높이 (src/ui/settings.ts:131)

## 못 돌린 것

- 로어북 호출 페이지의 「로어북 깊이」「로어북 토큰 예산」이 요청 글에 미치는 효과. 끄고 켜는 것과 저장만 봤다.
- 시작 전(시작 패널) 범위의 설정. 시작한 채팅만 봤다.
- 실제 Risu 에서의 동작. 가짜 Risu 로만 돌렸다.
- 폰 가로(land) 크기.
- 상점 외 기능(괴담넷·괴담톡·위키·홈쇼핑·몰)의 모델·재시도·턴 수가 요청에 반영되는지. 상점으로만 대표 확인했다.
- 참고(문제 아님): 단톡 수다 줄 수 「최대」에 최소(6)보다 작은 0 을 넣으면 저장은 1, 칸은 6 으로 보인다. 실제로 쓰는 값은 max(최소, 최대) = 6 이라 칸이 효과를 보여 주는 것으로 보았다 (src/core/phone.ts:143-144).
