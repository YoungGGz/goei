## 문제 1 (보통, 재현) Router 가 시간 제한에 걸려도 진행 창에는 성공으로 보임

- 누른 순서: 설정 Router 시간 제한 5초(`$pp_router_timeout 5`) → Router 답이 7.5초 뒤에 옴 → 한 턴.
- 기대: 라우터 칸이 시간 초과(실패)로 보이고 끝에 「1건 실패」. 근거: 11-22 이 동작을 「남은 것(사용자에게 알림, 안 고침): Router 시간 제한에 걸려도 진행 창은 성공으로 보임(전부터)」으로 사용자에게 알렸다(기억 goei-guides-router-1122). 실제로 그 턴 본편은 Router 답 없이 코드 Router 로 갔다.
- 실제: 본편은 5초에 넘어감(단계10 「본편 요청이 기다린 시간」 약 5,000ms). 그동안 진행 창은 제목 「메인 응답 대기」에 라우터 칸은 계속 run, 위 줄 글은 「보조 모델 · 보냄 829 토큰」(돌고 있는 Router 의 것). Router 답이 늦게 오자 라우터 done, 끝 「끝」, 실패 0.
- 증상: Router 가 매번 늦어 본편에 안 쓰이는데도 진행 창은 늘 성공이라 사용자가 알 길이 없다.
- 근거: `src/host/people.ts:791-794` Promise.race 가 시간 제한으로 끊고 넘어가도 `runModel` 은 계속 돌고, 늦게 끝나면 `src/host/llm.ts:120-124` 가 ok 로 적음. Director 도 같은 꼴(`src/host/people.ts:833-836`, 코드로만 확인). 단계10_Router_시간초과.txt.

- 근거: 리스너는 인터넷·위키·쇼핑몰을 기다리지 않고(`src/body.ts:763`, 차례로 `785-786`), 늦게 시작한 호출은 시작할 때 열린 턴에 붙음(`src/core/progress.ts:181` progressCallStart, `src/host/trace.ts:277` traceMark). 실제 Risu 도 리스너가 끝나면 다음 전송을 받는다(재검토 Codex 08).

- 근거: 진행 창은 `progressWatch`(`src/core/progress.ts` 감시 시간 progWatch)와 응답 훅으로만 닫히고 `onWaiting` 을 듣지 않음.

## 물을 것

1. **호출은 성공했는데 답을 못 쓴 경우의 진행 창 표시** (재현, 단계11·12): Router 답을 못 읽어 코드 Router 로 넘어간 턴, 갱신기 답을 재시도까지 두 번 다 못 읽어 기록이 안 바뀐 턴 모두 진행 창은 「끝」, 실패 0(갱신기 「· 2회」만 보임). 진행 창의 「실패」가 호출 실패만인지, 기능 실패(답을 못 씀)까지인지 정한 기록이 없음.
2. **호출 흐름 「생성 공통」에 「모델 오류 재시도」가 없음** (코드만 읽음): 화면 설명은 「호출 수와 모델을 바꾸는 값만 모았다」인데, 호출 수를 늘리는 「모델 오류 재시도」(기본 2회, `src/core/advanced.ts:62`)는 형식 오류 재시도·다시 보기와 달리 이 화면에 없음(`src/ui/editor/flowpage.ts` common).

## 확인한 것 (문제 아님)

- 미리 보기 예상과 실제 보낸 토큰: 같은 채팅 상태에서 Router·Director·갱신기 모두 몇 토큰 차(요청 머리 「[system]」 등 셈 차이)로 같다(단계04).
- 설정 조합 4가지에서 화면 예측 횟수·실제 호출 종류·진행 창 줄이 서로 맞는다(단계06~09). 위키는 「갱신기」 점 묶음, 괴담톡·게시판은 같은 모델이면 「통합」 한 칸 — 설계대로.
- 기록 0명이면 Router·Director 줄 「기록된 인물 없음」, 진행 창 칸도 없음(05 점검과 같음).
- 모델 실패·빈 답은 진행 창에 실패와 까닭 글로 보인다(단계13·14). 폰 막대 점·카드가 PC 와 같은 상태(단계19·20).

## 못 돌린 것

- 채팅 옮김 뒤 앞 채팅의 뒤 작업(단계18): 가짜 Risu 에서 채팅 번호만 바꿔서는 본체 감시가 옮긴 것으로 보지 않아 판정 못 함(적기만).
- 페이지 새로고침 중간·Director 시간 초과·괴담톡/게시판/관전 미리 보기와 실제 요청 비교(가짜 답이 실패라 형식 있는 답 흐름까지 못 감)·인물 갱신 여러 묶음(수동 「새 응답 읽기」)·정리 별도 호출이 실제로 도는 턴(상한 넘김 상태 필요)은 돌리지 않음.
