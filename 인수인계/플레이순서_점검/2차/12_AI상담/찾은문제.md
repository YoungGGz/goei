## 문제 1. 수 칸을 0(안 함·제한 없음)으로 바꾸면 바뀌었는데 「바꾸지 못했어요」가 뜨고 판이 없다 — 재현함

- 누른 순서: 설정 › 생성 공통 → AI 상담 「다시 보기를 1회로」 → 「응」(적용) → 「다시 보기 꺼 줘」(답 `<set>adv-set.gen:reiterate=0`) → 「응」(답 `<apply>yes</apply>`).
- 기대값: 값이 0 으로 바뀌고 「1회 → 안 함」 판이 남아 되돌릴 수 있다. 근거: consult.ts 머리(「적용 뒤 화면을 다시 읽어 정말 바뀌었는지 본다」), 판·되돌리기 설계(11-12 사용자 시안).
- 실제값: `$gen_reiterate` 는 0 으로 바뀜. 화면에는 「바꾸지 못했어요: 다시 보기」, 판 없음 → 되돌리기 단추도 없음.
- 까닭: 0 인 수 칸은 화면이 `value=""` + 자리 글(「안 함」「제한 없음」)로 그린다(src/ui/advanced.ts:39, famtable.ts:271). 목록은 그 빈 값을 지금 값으로 읽고(src/ui/editor/catalog.ts:151), 적용 판정은 `now.cur === p.value`(src/ui/editor/consult.ts:334)라 `'' ≠ '0'` 로 실패 처리.
- 같은 뿌리:
  - 요청 글에 빈 수 칸이 「지금: (비어 있음)」으로 감(`요청 토큰 상한`·`다시 보기`·`동시 요청`·`검색 깊이` 등 10줄, out/탐색_전부.txt). 화면은 「제한 없음」「안 함」을 보이는데 모델은 그 뜻을 받지 못한다. 판에도 「(비어 있음) → 1회」로 나옴(out/단계08b).
  - 모델이 화면 이름 그대로 `adv-set.gen:budget=제한 없음` 이라고 쓰면 「고를 수 없는 값」으로 빠짐(num 칸은 zero 이름을 안 받음, src/core/consult.ts:133·catalog.ts:151). 
- 플레이어 증상: 상담이 「껐어요」 했는데 「바꾸지 못했어요」가 같이 떠서 바뀐 건지 모름. 실제론 바뀌었고 되돌릴 판도 없다. 「제한 없음으로 해 줘」는 안 먹는다.
- 근거: out/단계08·08b·08c·08d·08e, 상태08.json.

## 문제 2. 「2만」 같은 값을 2 로 받아 적용한다 — 재현함

- 누른 순서: 설정 › 생성 공통 → 「요청 토큰 상한을 2만으로」(답 `<say>…2만 토큰으로 바꿀까요?</say><set>adv-set.gen:budget=2만</set>`) → 「응」(`<apply>yes</apply>`).
- 기대값: 받지 않고 알리거나(값 검사의 뜻, consult.ts 머리 「고를 수 없는 값, 범위 밖 수는 여기서 걸러 적용될 길이 없다」) 20000. 2 는 아님.
- 실제값: pending `2`, 알림 없음. 동의 턴에 `$gen_budget = "2"`, 판 「(비어 있음) → 2토큰」.
- 까닭: src/core/consult.ts:133 `/^-?\d+\s*\D{0,3}$/` 가 숫자 뒤 글자 3개까지 단위로 보고 버린다 → 「2만」「3천」「20k」「2만토큰」 이 앞 숫자만 남는다.
- 플레이어 증상: 상담원 말은 「2만 토큰」, 사용자는 그 말에 동의, 실제로는 요청 토큰 상한 2토큰(괴담넷·괴담톡·위키 요청이 거의 다 잘림). 판을 꼼꼼히 봐야 안다. 동의할 때 화면에 실제 적힐 값이 안 보여 말과 값이 달라도 모른다.
- 근거: out/단계09·09b(동의 요청의 [바꾸자고 한 것] `adv-set.gen:budget=2 (… 지금 (비어 있음))`), 상태09.json.

## 문제 3. 한 줄을 바꾸며 같이 바뀐 줄이 판에 없고, 되돌려도 안 돌아온다 — 재현함

- 누른 순서: 설정 › 소지품 → 「아바타 동작 간격 최소를 30초로」(`set-items-act-min.n=30`, 지금 최소 12·최대 24) → 「응」 → 판 「되돌리기」.
- 기대값: 되돌리면 바꾸기 전으로(최소 12·최대 24). 근거: 판 「되돌리기」의 뜻, src/ui/editor/consult.ts:325-327 주석(「한 줄을 바꾸면 다른 줄이 같이 바뀌는 설정이 있다」를 알고 있음).
- 실제값: 처리기가 최소 > 최대이면 최대도 30 으로 민다(src/ui/settings.ts:1045). 판에는 「최소 12초 → 30초」 한 줄만. 되돌리면 최소만 12, 최대는 30 으로 남음(`$it_act_gap_min 12 · $it_act_gap_max 30`).
- 플레이어 증상: 상담으로 최소만 바꿨다가 되돌렸는데 최대가 몰래 30초로 바뀌어 있다. 같은 꼴의 짝 칸(최소~최대 구간 설정)은 다 해당될 수 있음(이번엔 이 한 쌍만 돌림).
- 근거: out/단계07·07b, 상태07.json, src/ui/editor/consult.ts:330-336(판은 pending 줄만 적음), 되돌리기 같은 파일 ai-undo(판 줄만 되돌림).

## 문제 4. 꼴이 조금 틀린 `<set>` 줄은 말없이 버린다 — 재현함

- 누른 순서: 설정 › 인물 → 「인물 갱신을 수동으로」(답 `<set>\n- pp-set.when=수동\n</set>`, 글머리표 붙음) → 「응」.
- 기대값: 못 읽은 줄이 있으면 제안 턴에 알린다. 근거: 같은 코드가 목록에 없는 id·고를 수 없는 값은 「바꿀 수 없는 것은 뺐어요 …」로 알림(src/ui/editor/consult.ts:344); 지침 OUTPUT 의 꼴.
- 실제값: 줄 정규식(src/core/consult.ts:115)에 안 맞아 통째로 사라짐. 제안 턴 화면엔 「바꿀까요?」만 남고 알림 없음, pending 빔, 형식 오류 재시도도 안 함(`<say>` 가 있으니). 동의하면 「바꾸자고 한 것이 없어서 아무것도 바꾸지 않았어요.」
- 플레이어 증상: 「바꿀까요?」에 「응」 했는데 안 바뀐다. 왜인지 모른다.
- 근거: out/단계10·10b, 상태10.json.

## 문제 5. `<apply>` 안이 yes 가 아니면 「바꿨어요」 답만 남고 아무 안내 없이 버린다 — 재현함

- 누른 순서: 「인물 갱신을 수동으로」(정상 제안, pending `when=manual`) → 「응」(답 `<say>네, 수동으로 바꿨어요.</say><apply>네</apply>`).
- 기대값: 적용하거나, 적용 안 됐다고 알린다. 근거: 지침 CHANGE 「Never write that a setting was changed unless this reply carries <apply>yes</apply>」 — 모델이 어긴 때 코드가 받는 쪽. 같은 종류를 1차 재검토 홈쇼핑 문제4(「받았다고 했는데 아무 일 없음」, 모델이 지침을 어긴 때만)도 bug 로 봄.
- 실제값: `/<apply>\s*yes\s*<\/apply>/i`(src/core/consult.ts:116) 불일치 → pending 은 `me.pending = []`(src/ui/editor/consult.ts:316)로 버려지고 화면 마지막 줄은 「네, 수동으로 바꿨어요.」 값은 매 턴 그대로.
- 플레이어 증상: 상담이 바꿨다고 했는데 안 바뀜. 판도 알림도 없어 모른다.
- 근거: out/단계11·11b, 상태11.json.

## 문제 6. 요청 글: 「메시지당 변화 상한」 줄의 값·범위가 깨져 간다 — 재현함

- 기대값: 화면과 같은 값 꼴(「±10」 또는 10, 범위 0~100).
- 실제값: `[pp-cap] 호감 점수 · 메시지당 변화 상한 | 지금: 10±10 | 고를 수 있는 값: 0~100±10 (정수)`. range 칸 옆 `<output>±10</output>` 글을 단위로 읽음(src/ui/editor/catalog.ts:149, src/ui/people.ts:429). 0 일 때는 output 이 「한도 없음」이라 「0한도 없음」「0~100한도 없음」이 됨(코드로 확인, 돌리지는 않음).
- 플레이어 증상: 상담이 「지금 10±10」처럼 말하거나 값을 엉뚱하게 설명할 수 있다. 바꾸기 자체는 숫자만 쓰면 됨.
- 근거: out/단계02(요청 user), out/탐색_전부.txt.

## 문제 7. 글 칸 값의 따옴표를 그대로 저장한다 — 재현함

## 물을 것

1. **[지난 턴 실제]가 다른 채팅의 턴이다.** 호출 기록(`goei-trace`)은 기기에 하나이고 턴에 채팅 표시가 없다(src/host/trace.ts:45). 채팅 B 에서 상담하면 채팅 A 에서 돈 턴(Director 42초 실패 등)이 「지난 턴 실제」로 간다(out/단계20). 지침은 증상의 원인을 이 칸에서 먼저 읽으라고 하므로 다른 채팅 설정 기준의 진단이 나올 수 있다. 기록 보관 수를 기기 설정으로 둔 것은 사용자 결정이지만, 상담이 이 채팅이 아닌 턴을 써도 되는지는 정해진 근거가 없다.
2. **되돌리기·적용 실패가 상담 대화에 안 남는다.** 상담에 가는 대화는 사용자·상담 줄만(sys·판 제외, src/ui/editor/consult.ts:278). 되돌린 뒤 다음 요청의 대화엔 「바꿨어요」만 남는다(out/단계06). [설정 목록]에 지금 값이 가서 크게 틀리진 않으나, 「아까 바꾼 거 다시 해 줘」 같은 말에 쓸 정보가 없다. 넣을지 사용자 판단.

- 시작 전(새 채팅 기본값) 상담: tests/flow-consult-browser.mjs 4-2 와 같은 길이라 이번엔 안 돌림.

- 실제 모델 응답: 가짜 답만 썼다. 문제 2·4·5·7 은 모델이 지침 꼴을 어긴 때에만 생기며, 실제 모델(Gemini 3.7 Flash)이 얼마나 자주 그러는지는 모른다.
