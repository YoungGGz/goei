## 문제 1 (보통, 재현) 본체를 못 받은 채 보낸 본편 요청에 플러그인 표식이 그대로 감

- 누른 순서: 괴이 카드 열기(받기 404) → 받기 창이 뜬 채로 채팅에서 메시지 보냄(단계21→22).
- 기대: 모델에 가는 요청에 플러그인 표식(`%%GOEI_SCENE%%`, `[▣…]` 상태 줄 등)이 없다. 근거: 점검지침 3-A 「플러그인 내부 표식이 새나」, `src/body.ts` 머리 주석(어느 단계가 실패해도 정리 단계가 표식을 지움), `src/main.ts:174` 주석(본체가 던져도 표식만 지우고 보냄).
- 실제: 돌아온 요청이 원문 그대로. `첫 장면 글\n%%GOEI_SCENE%%`, `[▣|2025.03.14|…|1000]` 둘 다 남음(단계22 덧붙임에 전문).
- 증상: 받기 창을 닫고 그냥 채팅하면 모델이 표식 글자와 상태 줄 원문을 본다. 같은 까닭으로 화면 그리기(`onDisplay`)도 원문을 돌려줘 채팅에 표식이 보인다(이쪽은 코드만 읽음, 재현 안 함).
- 근거: `src/main.ts:164-170` — 본체가 없으면 `ensure()` 가 null 이고(실패 1분 안) `messages` 를 그대로 돌려줌. 표식 지우기(`sanitize`)는 본체에만 있음. `src/main.ts:194-198` 도 같음. 단계22 파일.

## 물을 것

### Q1. 받기 창을 거쳐 본체가 뜬 뒤, 처음 누른 「설치·업데이트」 화면을 이어서 열어야 하나
- 누른 순서: 내 봇에서 「설치·업데이트」 → 받기 실패 창 → (네트워크 복구) 「다시 받기」(단계25). 세계 자료 창의 「다시 받기」도 같음(단계94, 괴이 카드).
- 실제: 창이 닫히고 끝. 내 봇에서는 유령 단추도 없어 아무 변화가 없어 보인다. 설치하려면 사이드바 단추를 다시 눌러야 한다.
- 근거 코드: `src/main.ts:233-235` 콜백이 `ensure(true).then((b) => b?.install())` — 받기 창 경로에서는 null 로 끝나 `install()` 을 부르지 않음. 정한 기대값이 없어 문제로 단정하지 않음.

### Q2. 세계 자료 받기에 실패한 지 1분 안에 카드를 다시 열거나 「설치·업데이트」를 누르면 다시 받지 않고 지난 까닭만 보여 주는 것이 맞나
- 누른 순서: 세계 자료 받기 실패 → 「닫기」 → (네트워크 복구) 「설치·업데이트」(단계92→93).
- 실제: 아무것도 받지 않고 받기 창이 지난 까닭(「플러그인이 옛 판 …」)으로 다시 뜸. 창의 「다시 받기」를 누르면 받음(단계94).
- 근거 코드: `src/host/datapack.ts:125` 1분 억제는 받기 창의 「다시 받기」(force)만 넘음. 본체 받기는 카드를 다시 열면 바로 다시 받는다(`src/main.ts:22` 주석, 단계31). 두 쪽이 다르다. 의도인지 물음.

### Q3. 위키 기본 문서·토크나이저는 손으로 받아야 하는 것이 맞나 (릴리스 안내와 다름)
- 누른 순서: 배포 카드를 가져와 처음 엶 → 유령 단추(단계01·02) → 「설치·업데이트」(단계03).
- 실제: 본체·세계 자료만 저절로 받고, 위키 기본 문서·토크나이저는 「없음」(빠진 것 2개). 「빠진 것 전부 채우기」를 눌러야 받음(단계04). 카드에도 위키 묶음이 없다(로어북 3개).
- 증상: 안내대로만 설치하면 위키 탭의 기본 문서(괴이·장소 설명)가 비고, 상점 요청의 위키 참고 자료(`src/ui/shop.ts:356`)도 빈다. 토큰 수는 어림값.
- 근거: 릴리스 안내 `.github/workflows/release.yml:85` 「괴이 카드를 열면 나머지 파일을 자동으로 받습니다」(사용자가 확인한 글). 자동으로 받는 길 없음(`installWikiPack` 은 `src/ui/editor/install.ts:172`·`manage.ts:447` 단추로만). 설정 문구는 「안 받으면 … 비어 있어요」(`manage.ts:241`)라 손으로 받는 설계일 수도 있음.
