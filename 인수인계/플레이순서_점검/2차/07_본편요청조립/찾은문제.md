## 문제

### 문제1 (재현) 첫 응답에 상태창 줄이 없으면 둘째 턴부터도 「지금이 첫 턴」이라고 보냄
- 누른 순서: 시작 화면 출발 → 첫 전송 → 상태창 줄이 빠진 응답 → 둘째 전송 (`out/단계F02_상태창줄없는응답뒤_요청.txt`).
- 기대값: 둘째 턴 요청에 첫 턴이라는 말이 없다. 근거: 지침 `메인요청_덧붙임.txt` STATUS.FIRST 글 자체가 「No status line yet: this is the first turn.」이고, 코드 주석(`src/core/statusctx.ts:104` 「첫 턴(상태창 줄이 아직 없음)」)도 첫 턴용으로 적음.
- 실제값: `[Previous status]\nNo status line yet: this is the first turn.\nStarting values: Balance = 140000 …` 가 둘째 턴에 감.
- 증상: 모델이 앞 장면을 무시하고 새 이야기의 첫 턴처럼 쓸 수 있다. 날짜·시각·장소는 아무 데도 안 넘어가고 잔고만 넘어간다.
- 근거: `src/core/statusctx.ts:99-112` (요청에 상태창 줄이 하나도 없으면 턴과 상관없이 FIRST 블록).

### 문제2 (재현) 잔고·포인트 칸을 끄면 첫 턴에 [Previous status] 블록이 없는데, 같은 요청의 상태창 지침은 「그 블록이 온다」고 함
- 누른 순서: 시작 화면 출발 → `$st_col_wallet=off` → 첫 전송 (`out/단계E01_잔고칸끔_첫턴.txt`).
- 기대값: 지침과 조립이 같은 말. 근거: 같은 요청 Tag 상태창 절의 STATUS.RULE.PREVIOUS 「The status line of the previous scene is provided in a `[Previous status]` block just before the latest user input; follow the note in that block.」
- 실제값: 블록 없음, 규칙 줄은 그대로.
- 증상: 첫 턴에 모델이 없는 블록을 찾는다. 잔고가 없을 때 첫 상태창 값의 출발점이 없다(작음).
- 근거: `src/core/statusctx.ts:104-108` (넘길 시작 값이 없으면 블록을 안 넣음), `src/core/world/statuscols.ts:198` (규칙 줄은 늘 넣음).

### 문제3 (재현) 인터넷 몰 접속 표식이 지침에 없는 내부 꼴(`@web:cos`)로 다음 본편 요청에 감
- 누른 순서: 첫 전송 → 응답 끝에 `[shop: 우주 쇼핑몰|@web]` → 둘째 전송 (`out/단계F01_접속표식_다음요청.txt`).
- 기대값: 플러그인 내부 표식이 모델에 안 감(점검 지침 3-A 「넣지 말아야 할 것: 플러그인 내부 표식」). 지침 `상점.txt:161` 은 주인 이름에 `@web` 만 쓰라고 함.
- 실제값: 저장 본문이 `[shop: 우주 쇼핑몰|@web:cos]` 로 바뀌고, 그 마지막 응답이 history 로 그대로 감.
- 증상: 모델이 자기 앞 응답에서 사이트 id 를 본다. 따라 써도 처리 쪽은 `@web` 으로 시작하면 받으므로 동작은 같다(작음).
- 근거: `src/core/shop.ts:534,541-546` (webRaw 로 고쳐 씀), `src/core/sanitize.ts:13` PLUGIN_MARKERS 에 없음.

## 확인만 한 것 (문제 아님)
- 덧붙임 자리: 참고 기록(시청 기록) → [Previous status] → [Inventory] → [People records] → 마지막 유저 글 → 이미지 지침(맨 끝, Asset depth 0 자리). 로어 덩어리는 첫 장면 앞에 하나. PC·폰 첫 요청은 글자까지 같다.
- 겹침: [Previous status] 에 Fields 줄이 Tag 상태창 절과 겹쳐 오지 않음. 산 물건이 Recently 와 just bought 에 두 번 오지 않음(1차 고침 그대로).
- 한 번만 전달: 구매·사용·상점 사건은 그 턴 한 번, 넷째·다섯째 턴엔 없음. 목록엔 남음(송연먹 19회). Recently 줄은 설정 기간 동안 남는 기록 줄이라 사건 되풀이가 아님.
- 다시 굴리기: 셋째 턴을 다시 굴리면 구매·사용이 다시 실리고 [Previous status] 는 둘째 응답 줄(잔고는 장부 90000). 자동 재시도(같은 요청이 다시 옴)는 덧붙임이 두 번 끼지 않고, 그다음 새 요청은 다시 조립.
- 설정: 검색 깊이 2 → 앞 턴에만 나온 에일린 로어북 빠짐. 로어북 예산 300 → 요원 글 줄어듦. 컨텍스트 총 상한 200·홈쇼핑 상한 300·넘기기 끔·넘기는 기간 1 → 시청 기록 덩어리 빠짐. 인물 끔·소지품 끔·에셋 끔(옛 이미지 태그도 지움)·에셋 보조 모델·세력 요약/요원 명단 끔·잔고 칸 끔(줄·Balance 규칙·최근 거래 빠짐) 모두 설정대로.
- 실패: 로어·주인공·명부 다듬기·참고 기록·상태창·소지품·망상홈쇼핑·인물 기록·이미지 지침·기록 태그 정리·옛 이미지 태그·채팅 읽기·beforeRequest 를 하나씩 던지게 해도 그 단계 것만 빠지고 표식·상황판 태그는 안 샘.
- 지난 응답의 상점 표식은 마지막 응답 것만 history 에 남는다. 모델 자신의 출력이고 표식 지침과 같은 꼴이라 상태창 줄처럼 둔 것으로 봄.
- 시청 기록은 넘기는 기간 0(기본 「다음 편성까지」) 동안 매 턴 같은 덩어리로 감 — 설정 설명 그대로.
