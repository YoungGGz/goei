# 플레이 순서 점검 지침 (초안, 11-22)

이 저장소(ygberserk/goei, 브랜치 `claude/project-thread-kd1w8j`)는 RisuAI 플러그인 「괴이」다. 이 글은 Claude 가 하려는 점검 방법이고, GPT 는 이 방법 자체가 맞는지와 Claude 가 찾은 결과를 교차로 본다.

## 왜 이 점검을 하나

기존 시험(단위 1,200여 개)은 코드가 짠 사람의 생각대로 도는지만 봤다. 실제로 한 판 하자 아래가 바로 나왔다. 전부 코드와 요청 글을 읽으면 보이는 것이었다.

- 상점에서 다 사고 새로고침하면 같은 물건이 다시 나옴 (산 물건이 「다시 내지 말 것」 목록에서 빠짐)
- 호칭 낱말(예: 「선배」)로 엉뚱한 인물 기록이 생김
- 인물 기록이 0명인데 Router 가 도는 것처럼 표시됨
- 망상홈쇼핑 상담원이 수락을 받고도 전화를 끊음
- 상점 값이 말이 안 됨

## 방법

기능 하나를 잡고 **플레이어가 실제로 하는 순서대로** 끝까지 따라간다. 단계마다 두 가지를 뽑는다.

1. **모델에게 가는 요청 글 전문** (system·user·assistant 메시지 그대로, 설정 기본값 상태). 모델 호출은 `src/host/llm.ts` 를 거치고 `src/host/trace.ts` 가 기록한다.
2. **그 단계 뒤 저장된 상태** (채팅 변수·소지품·가계부·인물 기록 등 다음 단계 요청 글에 들어가는 것).

그리고 각 단계에서 묻는다.

- 이 글만 받은 모델이 말이 되는 답을 낼 수밖에 없나? 답에 필요한 정보(지금 장면, 가진 돈, 이미 산 것, 앞에서 한 말)가 다 들어 있나?
- 앞 단계에서 정해진 것(값, 수락, 산 물건, 정한 호칭)과 어긋나는 글이 있나? 앞 단계 결과가 이 단계 글에 실제로 들어갔나?
- 화면에 보이는 것과 요청 글·저장 상태가 같은 말을 하나? (예: 「Router 도는 중」 표시인데 실제로는 부를 대상이 0명)
- 모델 답을 코드가 읽어 들이는 곳(파싱)이 답이 조금 다르게 와도 맞게 받나? 못 받으면 화면과 상태가 어떻게 되나?
- 같은 단계를 두 번 하거나(새로고침 연타), 순서를 바꾸거나(사기 전에 나가기), 다시 불러오면(새로고침·채팅 재진입) 상태가 맞게 남나?

모델을 실제로 부르지 않아도 위 질문은 글과 코드로 답할 수 있다. 「실제 모델로 안 돌려 봐서 모른다」는 결론으로 쓰지 않는다.

## 기능별 순서

### 1. 상점 (`src/core/shop.ts`, `shopctx.ts`, `shopfn.ts`, `src/ui/shop.ts`)
열기 → 상점 주인에게 말 걸기 → 흥정(깎기·거절) → 하나 사기 → 남은 것 다 사기 → 본편 다음 턴 → 상점 다시 열기 → 새로고침 → 가진 물건 팔기 → 나가기 → 본편 다음 턴에 산 것·쓴 돈이 반영되는지

### 2. 몰 두 곳: 우주 쇼핑몰, 백일몽 포인트몰 (`src/core/malls.ts`, `points.ts`, `src/ui/malls.ts`)
열기(자동 호출 기본값은 수동) → 목록 받기 → 장바구니 담기 → 결제(돈/포인트 부족 포함) → 배송·도착이 본편에 들어가는지 → 다시 열기·새로고침 → 포인트는 백일몽 소속일 때만

### 3. 망상홈쇼핑 (`src/core/homeshop.ts`, `hspeel.ts`, `consult.ts`, `src/ui/homeshop.ts`)
방송 보기 → 스티커 떼기 → 전화 걸기 → 상담원 첫 말 → 흥정·질문 → 말로 수락(`<deal/>`) / 단추로 주문 → 주문 뒤 상담원 말 → 끊기(수락 전·후) → 본편 다음 턴에 주문·결제가 들어가는지 → 지난 주문 넘김

### 4. 인물 기록 (`src/core/people/` 의 router·updater·inject·identity)
새 인물 처음 나옴 → 이름 없이 호칭만 나옴 → 같은 인물 다른 호칭 → 기록 0명일 때 → Router 선택 요청 → 기록 갱신 요청 → 본편에 들어가는 인물 글 → 오래 안 나온 인물 → 채팅 다시 불러오기

### 5. 커스텀 임무 (`src/core/scenarios.ts`, `scenes.ts`, `lore.ts`, 첫 장면 로어북 설정)
새 채팅에서 커스텀 임무 고르기(직접 입력·소속별) → 첫 요청 글(첫 장면 로어북 포함 여부) → 채팅 중에 임무 고르기(지금 장면을 끊지 않고 이어가는지) → 다음 턴들 → 임무 바꾸기·끄기

## 남기는 것

기능마다 `인수인계/플레이순서_점검/<번호>_<기능>/` 아래에:
- `단계NN_<단계이름>.txt`: 그 단계 요청 글 전문 (설정 기본값, 시험용 채팅 상태 명시)
- `상태NN.json`: 그 단계 뒤 저장 상태
- `찾은문제.md`: 문제마다 「어느 단계 / 무엇이 빠지거나 어긋남 / 화면에서 겪는 일 / 근거 줄(파일:줄)」. 고치기 전 목록이다.

요청 글은 실제 코드 경로로 만든다(시험용으로 따로 짠 글이 아님). 뽑는 스크립트도 같은 폴더에 둬서 GPT 가 다시 돌려 볼 수 있게 한다.

## 진행 규칙

- 기능 하나 끝나면 바로 찾은 목록을 올린다. 몰아서 올리지 않는다.
- 고치는 것은 목록을 사용자가 보고 「해」 한 뒤에만.
- 지침 글을 고칠 때는 하드코딩·메타 낱말 없이 평이하게. 사용자 설정·기본값을 코드로 덮지 않는다.
