# 플레이 순서 점검 지침 (초안 2판, 11-22)

저장소 ygberserk/goei, 브랜치 `claude/project-thread-kd1w8j` (main = v0.21.32 와 같은 코드). RisuAI 플러그인 「괴이」.
이 글은 점검 방법이다. GPT 는 ① 이 방법에 빠진 것이 없는지, ② 점검 결과(나중에 이 폴더에 올라옴)가 맞는지를 본다. 코드를 직접 읽어도 된다.

---

## 1. 왜 이 점검을 하나

기존 시험(단위 1,200여 개)은 「코드가 짠 사람 생각대로 도는가」만 봤다. 실제로 한 판 하자 아래가 바로 나왔다. 모두 요청 글과 코드를 따라가면 보이는 것이었다.

| 나온 것 | 종류 |
|---|---|
| 상점에서 다 사고 새로고침하면 같은 물건이 또 나옴 (산 물건이 「다시 내지 말 것」 목록에서 빠짐) | 앞 단계 결과가 다음 요청 글에 안 들어감 |
| 호칭 낱말(예: 「선배」)로 엉뚱한 인물 기록이 생김 | 모델 답을 받아들이는 쪽이 너무 느슨함 |
| 인물 기록 0명인데 Router 가 도는 것처럼 표시 | 화면 표시와 실제 상태가 다름 |
| 망상홈쇼핑 상담원이 수락받고도 끊음 | 지침 글과 처리 코드가 서로 다른 말을 함 |
| 상점 값이 말이 안 됨 | 요청 글에 판단 근거가 모자람 |

이 다섯 종류가 다른 기능에도 있는지 찾는 것이 목표다.

## 2. 방법

기능 하나를 잡고 **플레이어가 실제로 하는 순서대로** 끝까지 따라간다. 각 단계에서 세 가지를 뽑는다.

1. **모델에게 가는 요청 글 전문**: system·user·assistant 메시지 그대로. 모든 보조 호출은 `src/host/llm.ts` 의 `generate`·`runModel` 을 거치고, 본편 요청은 `src/body.ts` 가 조립한다. 요청 글은 실제 코드 함수로 만든다(시험용으로 따로 쓴 글 금지).
2. **그 단계 뒤의 저장 상태**: 채팅 변수(`scriptstate`)의 관련 값 — 상점 상태, 소지품, 가계부, 인물 기록, 주문 등.
3. **화면에 보이는 것**: 그 상태를 UI 코드가 어떻게 그리는지(버튼 켜짐·꺼짐, 표시 글, 숫자).

모델 답은 실제 모델 대신 **여러 꼴의 가짜 답**을 넣어 처리 코드를 돌린다: 지침대로 잘 쓴 답 / 블록 하나 빠진 답 / 꼴이 조금 틀린 답(칸 수, 꺾쇠, 숫자 표기) / 지침과 반대로 행동한 답(예: 수락했는데 끊기 표식) / 빈 답.

실제 카드 자료(`카드/원본_봇카드.jpeg` 에서 `python3 -I tests/extract_module.py` 로 푸는 로어북 166개)를 쓴다. 장소·인물은 로어북에 있는 것만 쓴다.

## 3. 각 단계에서 묻는 것

**A. 요청 글**
- 이 글만 받은 모델이 말이 되는 답을 낼 수밖에 없나? 판단에 필요한 정보(지금 장면·시각·장소, 주인공이 누구인지, 앞에서 한 말, 이미 산 것, 정해진 값)가 다 있나?
- 앞 단계에서 정해진 것이 이 글에 실제로 들어갔나? 지난 것이 지워져야 할 때 남아 있지 않나?
- 넣지 말아야 할 것이 들어갔나? (잔고처럼 일부러 빼기로 한 것, 숨긴 진짜 효과, 다른 가게 것, 지난 턴 것의 되풀이)
- 지침 절끼리 서로 다른 말을 하지 않나? 지침 글과 처리 코드가 같은 표식·꼴을 쓰나?
- 같은 정보가 두 번, 다른 말로 들어가 헷갈리게 하지 않나?

**B. 답 처리**
- 잘 쓴 답을 맞게 받나? 조금 틀린 답에서 엉뚱한 것을 받아들이지 않나(없던 인물·물건이 생김, 값이 0원 등)? 못 받으면 사용자에게 무엇이 보이고 상태는 어떻게 남나(반쯤 저장되지 않나)?

**C. 상태와 화면**
- 화면 표시가 실제 상태와 같은 말을 하나?
- 다음 단계(같은 기능의 다음 요청, 그리고 **다음 턴 본편 요청**)에 결과가 들어가나? 본편이 알아야 하는 일(산 것, 판 것, 주문, 쫓겨남, 받은 물건)이 본편 요청 글에 한 번만, 맞는 턴에 들어가나?

**D. 순서와 되풀이**
- 같은 단계를 두 번(연타, 새로고침 연타), 순서를 바꿔서(사기 전에 나가기, 답 기다리는 중 다른 단추), 되돌려서(본편 응답 다시 굴리기·지우기, 플러그인 창 닫았다 열기, 페이지 새로고침, 다른 채팅 갔다 오기) 해도 상태가 맞게 남나?

**E. 설정 갈래**
- 그 기능 설정을 기본값에서 바꾸면(켬·끔, 자동·수동, 컨텍스트 포함 끔, 개수 최소·최대) 요청 글과 동작이 설정대로 바뀌나? 설정이 코드에 박힌 값으로 덮이지 않나?

모델을 실제로 안 불러도 위 질문은 글과 코드로 답할 수 있다. 「실제 모델로 안 돌려 봐서 모른다」를 결론으로 쓰지 않는다.

## 4. 모든 기능에 공통으로 넣는 갈래

| 갈래 | 보는 것 |
|---|---|
| 응답 실패 | 블록 빠짐·꼴 틀림·빈 답·시간 초과·재시도 뒤 성공. 내 말이 남나, 되돌려지나, 다시 보낼 수 있나 |
| 기다리는 동안 | 답 오기 전에 창 닫기·다른 단추·다른 채팅. 늦게 온 답이 엉뚱한 채팅·상태에 붙지 않나 |
| 본편 다시 굴리기 | 그 턴에 산 것·판 것·주문·기록이 같이 되돌아가나, 돈이 맞나, 다시 살 수 있나 |
| 본편 응답 지우기 | 위와 같음 |
| 다음 턴 | 결과가 본편 요청 글에 한 번만 들어가고 그다음 턴엔 안 들어가나 |
| 페이지 새로고침·채팅 다시 열기 | 저장 상태만으로 화면·다음 요청이 그대로 이어지나 |
| 설정 끔 | 끄면 요청 글에서도 빠지고 화면 카드도 안 뜨나, 켜면 돌아오나 |
| 컨텍스트 포함 끔·챗로그 턴 수·참조 로어북 수 | 요청 글이 설정대로 줄어드나 |
| 자동 호출 / 수동 | 자동이면 맞는 턴에 한 번만 도나, 다시 굴려도 또 안 도나, 수동이면 안 도나 |
| 보조 모델 / 메인 모델 선택 | 고른 모델로 가나 |
| PC / 폰 | 같은 동작이 두 배치에서 다 되나 (배치 모양은 다름이 정상) |

## 5. 기능별 순서

순서는 사용자가 정한 대로 1~5 를 먼저, 그 뒤 6~14.

### 1. 상점 (`src/core/shop.ts`, `shopctx.ts`, `shopfn.ts`, `src/ui/shop.ts`, 지침 `지침/상점.txt`)
1. 본편 응답에 `[shop: 가게|주인]` 표식이 붙음 → 카드 뜸 (표식 판단을 메인 모델이 할 때 / 갱신기가 할 때 / 주인공 자기 가게 / 고유 상점·인터넷 몰 이름)
2. 열기 → 첫 진열 요청(정체·주인 첫 말·진열대)
3. 물건 눌러 묻기 → 문의 요청
4. 흥정: 깎아 달라 / 다른 대가 제안 / 주인이 거절·역제안·수락 / 끊기(설정 켬·끔)
5. 없는 물건 찾기 → 들여옴(설정 「문의로 물건 바꾸기」 켬·끔) / 전부 바꿔 달라
6. 하나 사기 (잔고 충분·부족, 원이 아닌 대가, 희귀·특가)
7. 남은 것 다 사기 → 빈 진열대 화면
8. 본편 다음 턴 → 본편 요청 글에 산 것·나눈 말이 한 번
9. 같은 가게 표식이 다시 붙음 → 다시 열기 (상태 이어짐) / 표식이 안 붙음 → 상태 비움 / 다른 가게
10. 새로고침 → 다시 진열 요청(지난 진열·산 것 피하기, 이번 방문 대화 기억)
11. 팔기: 소지품 고름 → 값 묻기 → 흥정 → 「판매」 단추 / 말로 수락(`<deal/>`) / 주인이 안 삼 / 그만
12. 나가기 → 다음 턴 본편 요청 글
13. 포인트 상점(백일몽 소속일 때)과 원 상점의 차이

### 2. 우주 쇼핑몰 (`src/core/malls.ts`, `orders.ts`, `src/ui/malls.ts`, 지침 `우주쇼핑몰.txt`)
열기(자동 호출 기본 수동) → 진열(숨긴 진짜 효과·광고 문구, 진실 미리 정하기 설정) → 운영자 문의 → 정보 쪽지 사기 → 맞춤 주문 견적·선납 → 납기 지나 받기 → 사기·장바구니 → 받는 법(ARRIVE)이 본편에 → 팔기 → 다시 열기·새로고침 → 산 물건을 쓰는 턴에 진짜 효과가 본편에

### 3. 백일몽 포인트몰 (`src/core/malls.ts`, `points.ts`, `bmdesk.ts`, 지침 `백일몽포인트몰.txt`, `포인트몰_1대1상담.txt`)
백일몽 소속일 때만 → 열기 → 진열(포인트 값) → 사기(포인트 부족 포함) → 주문 조회·받으러 가기(PICKUP_TRY, 갈 수 없는 상황) → 받음 → 1:1 상담 → 다시 열기·새로고침. 다른 소속에서 포인트가 보이거나 쓰이지 않나

### 4. 망상홈쇼핑 (`src/core/homeshop.ts`, `hspeel.ts`, `hslog.ts`, `src/ui/homeshop.ts`, 지침 `망상홈쇼핑.txt`)
편성(자동 호출) → 방송 보기 → 내 채팅 보내기 → 진행자·시청자 반응 → 스티커 떼기 → 전화 걸기 → 상담원 첫 말 → 질문·흥정·맞교환 제안 → 말로 수락(`<deal/>`) / 단추로 주문 → 주문 뒤 상담원 말 → 끊기(수락 전·후, 상담원이 끊음·내가 끊음) → 다음 턴 상자 도착(ARRIVE) → 상자 열기 → 할부·방청 신청 턴 → 지난 주문 넘김 → 돈이 없을 때(가계부 끔)

### 5. 인물 기록 (`src/core/people/`, `src/host/people.ts`, 지침 `Router.txt`, `Director.txt`, `갱신기_*.txt`)
1. 기록 0명인 새 채팅 → 첫 턴 (Router·Director·갱신기가 도나, 화면 표시)
2. 새 인물이 이름과 함께 처음 나옴 → 갱신기가 기록 만듦
3. 이름 없이 호칭만 나옴(선배·아저씨·직원) → 기록이 생기면 안 됨
4. 같은 인물이 다른 호칭·별칭으로 나옴 → 같은 기록에 붙나
5. 명부(로어북) 인물 / 명부 밖 인물
6. Router 요청 → 장면 인물 고르기 → 본편에 들어가는 인물 글
7. Director 요청(설정 scene·facts·끔)
8. 매 턴 / 수동 갱신, 한 번에 읽는 응답 수
9. 오래 안 나온 인물, 기록 정리(consolidate)·줄이기(prune)
10. 호감·말투·관계 축 바뀜이 다음 턴 인물 글에
11. 본편 다시 굴리기·지우기 → 그 응답으로 생긴 기록 변화가 되돌아가나
(성적 기록 절 `sexual.ts` 은 사용자 지시로 고치지 않는다. 읽고 어긋남만 적는다)

### 6. 커스텀 임무·시작·첫 장면 (`src/core/scenarios.ts`, `scenes.ts`, `seed.ts`, `lore.ts`, `src/ui/editor/start.ts`, 지침 `이동_임무_지시문.txt`, `RP지침.txt`)
시작 화면에서 소속·시작 상황 고르기(소속별, 직접 입력, 커스텀 임무) → 첫 요청 글(첫 장면 로어북 「세계 › 조직 › 기본 세력 기록 › 첫 장면에 함께 넣을 로어북」, 시드) → 첫 응답 → 둘째 턴(시드가 빠지나) → 채팅 중에 커스텀 임무 고르기(지금 장면을 끊지 않고 이어가나) → 다음 턴들 → 임무 바꾸기·끄기 → 첫 전송 다시 굴리기

### 7. 본편 요청 조립 (매 턴, `src/body.ts`, `src/core/statusctx.ts`, `items.ts`, `people/inject.ts`, `imgprompt.ts`, 지침 `메인요청_덧붙임.txt`, `상태창_태그.txt`)
한 요청에 들어가는 덧붙임 전부(주인공·로어 보정·명부·참고 기록·상태창·소지품·망상홈쇼핑·인물 기록·이미지 지침·시드)를 한 번에 놓고 본다: 서로 겹치거나 다른 말을 하지 않나, 자리(마지막 유저 메시지 앞)가 맞나, 한 단계가 실패하면 나머지가 어떻게 되나, 플러그인 표식이 모델에 새지 않나

### 8. 소지품·가계부 (`src/core/items.ts`, `itemrules.ts`, `wallet.ts`, `src/host/usebox.ts`)
「다음 메시지에 사용」 넣기 → 보냄 → 소모 횟수 → 다 씀 / 장착·벗기 / 버리기 / 합치기 / 본문에서 잃음·두고 옴 / 무게 넘침 / 칸 넘침 / 다시 굴리기(사용이 다시 실리나, 두 번 쓰이지 않나) / 가계부 수동 조정

### 9. 괴담넷·게시판·DM (`src/core/gnet.ts`, `gnetPrompt.ts`, `boards.ts`, `src/ui/gnet.ts`, 지침 `괴담넷.txt`, `괴담갤.txt`, `세정게.txt`, `연어마켓.txt`)
자동 생성 턴 → 글 목록 → 글 열기 → 댓글 쓰기 → 답글 → DM 보내기·답장 → 본편에 넘기는 것(설정) → 다시 굴리기

### 10. 괴담톡 (`src/core/phone.ts`, `phonePrompt.ts`, `src/ui/phone.ts`, 지침 `괴담톡.txt`)
방 열기 → 보내기 → 답장 기다림 → 단톡·초대 → 확인 → 본편에 넘기는 것 → 다시 굴리기

### 11. 괴이위키 (`src/core/wiki.ts`, `src/ui/wiki.ts`, 지침 `괴이위키.txt`)
검색 → 없는 문서 만들기 → 다시 쓰기 → 기본 문서와 만든 문서 → 상점·상담 요청이 위키 문서를 참고 자료로 받는 길

### 12. AI 상담(설정 편집) (`src/ui/editor/consult.ts`, 지침 `AI상담.txt`)
질문 → 답 → 설정 바꾸기 제안 → 적용

### 13. 이미지 태그 보충 (`src/host/asset.ts`, 지침 `이미지_보조모델.txt`)
에셋 출력 켬·끔, 보조 모델로 태그 붙이기, 옛 태그 지우기

### 14. 호출 흐름 미리 보기·진행 창 (`src/ui/editor/flow.ts`, `src/core/progress.ts`)

## 6. 남기는 것

기능마다 `인수인계/플레이순서_점검/<번호>_<기능>/` 아래:
- `run.mjs` — 단계를 차례로 돌려 요청 글·상태를 뽑는 스크립트. 실제 코드 함수를 esbuild 로 묶어 부른다. 누구나 `node 인수인계/플레이순서_점검/<폴더>/run.mjs` 로 다시 돌릴 수 있게.
- `단계NN_<이름>.txt` — 그 단계 요청 글 전문과, 넣은 가짜 답
- `상태NN.json` — 그 단계 뒤 저장 상태
- `찾은문제.md` — 문제마다: 어느 단계·갈래 / 무엇이 빠지거나 어긋남 / 화면에서 겪는 일 / 근거(파일:줄). **고치기 전 목록**이다.

## 7. 진행 규칙

- 사용자가 「해」 한 뒤에 시작한다.
- 기능 하나 끝나면 찾은 목록을 바로 올린다. 몰아서 올리지 않는다.
- 고치는 것은 목록을 사용자가 보고 「해」 한 뒤에만.
- 지침 글을 고칠 때는 하드코딩·메타 낱말 없이 평이하게. 사용자 설정·기본값을 코드로 덮지 않는다.
