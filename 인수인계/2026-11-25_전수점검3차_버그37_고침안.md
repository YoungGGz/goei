## 가. 뿌리가 같은 묶음 (한 번 고치면 여럿이 같이 고쳐짐)

### 1. 「괴이 채팅인가」를 그릴 때마다 정확히 판정 — R02, R03
- **무엇**: 다른 봇 채팅에 들어간 직후, 괴이 판정(1초마다 도는 감시)이 아직 앞 채팅 값이라 다른 봇 글의 `[▣|…]`·`[shop:…]` 가 괴이 카드로, `<img=…>` 가 빈 그림 칸으로 그려진다.
- **고치는 법**: 화면 처리기(onDisplay)가 그릴 때 지금 캐릭터 번호를 읽고, 그 캐릭터가 괴이 카드인지(번호별로 기억) 본다. 괴이가 아니면 글을 그대로 돌려준다. 지금 있는 「표식이 있으면 우리 글로 본다(ours)」 짐작은 없앤다. 에셋 목록도 「어느 캐릭터 것인지」 적어 두고, 다른 캐릭터 것이면 다시 읽은 뒤 그린다.
- **같이 바뀌는 곳**: 요청 처리의 같은 짐작(`body.ts:252` 다른 봇 요청의 옛 그림 태그 빼기)도 같은 판정으로. 공-22(다른 봇은 손대지 않음)와 맞음.
- **나쁜 점**: 메시지를 그릴 때마다 리스AI 에 캐릭터 번호를 한 번 묻는다(가벼운 호출, 결과는 번호별로 기억).

### 2. 생각 블록은 어디서도 본문으로 안 읽음 — R01
- **무엇**: `<thinking>` 은 생각으로 안 떼고, 상태창·그림 태그는 `<think>` 안 것도 화면·가계부가 읽는다.
- **고치는 법**: `core/thoughts.ts` 한 곳에 생각 태그 이름(thoughts·thinking·think)을 두고, 「생각 블록 밖 글에만 함수 적용」 도우미를 만든다. 상태창 찾기(`findStatusTags`)와 화면 그리기(displayNow)가 이것을 쓴다. 그러면 가계부 맞춤·상태창 시간줄·상점 카드·그림 칸이 모두 생각 밖만 본다.
- **같이 바뀌는 곳**: 상황판·이미지 보조·상점 표식은 이미 떼고 있어 태그 이름만 늘어난다. 저장 본문의 생각 블록은 그대로 둔다(L-07).

### 3. 채팅 저장 권한·저장 실패를 알림 — R23, R24, R31
- **무엇**: 리스AI 「데이터베이스 수정」 권한을 거절하면 저장이 조용히 안 되는데 플러그인은 된 줄 안다(괴담톡 글 사라짐, 출동이 지시문 없이 나감 등). 그리고 「데이터베이스 전체 접근」은 처음 셋을 물은 뒤 2초 뒤에 따로 묻는다.
- **고치는 법**:
  - 처음 켤 때 한 번에 묻는 권한에 `db`(읽기)·`dbWrite`(쓰기)를 더한다(`main.ts`). 리스아이 소스 확인: 이렇게 물어 두면 그 세션 동안 다시 안 묻는다.
  - 채팅 저장(`host/risu.ts` saveChat) 한 곳에서, 쓰기 전에 쓰기 권한을 확인(이미 답한 것은 리스아이가 기억해 바로 돌아옴)하고 없으면 「저장 권한이 없어요」 오류를 던진다. 이미 오류를 받아 안내하는 곳(괴담톡·게시판·위키·출동·명부 등)은 그 안내가 뜨고, 안 받는 곳(괴담넷 글쓰기 `gnet.ts` writePost, 위키 `wiki.ts:239`)은 결과를 보게 고친다. 괴담톡은 실패하면 쓴 글을 입력칸에 돌려준다.
- **나쁜 점**: 첫 켤 때 묻는 권한이 셋 → 다섯. 리스아이의 「3일마다 다시 묻기」가 세션 중간에 안 뜬다(처음에 한꺼번에 물으니까).

### 4. 기다리는 사이 채팅 번호가 밀려도 원래 채팅에 저장 — R09
- **무엇**: 답을 기다리는 중 새 채팅·채팅 지우기·가져오기로 번호가 밀리면, 몰·상담·게시판·상점·홈쇼핑·위키 답이 그 번호의 다른 채팅에 저장된다. 괴담톡 답은 버려진다.
- **고치는 법**: 저장 함수(updateChat)에 「채팅 id」를 같이 넘기게 한다. 저장 직전 읽은 채팅 id 가 다르면, 그 캐릭터의 채팅을 찾아(가까운 번호부터) 같은 id 의 채팅에 저장한다. 없으면(지운 채팅) 저장하지 않고 버린다. 기다리는 호출(몰·상담·게시판·상점·홈쇼핑·위키·괴담톡·이미지 보충)은 요청을 보낼 때 채팅 id 를 잡아 두고 그것으로 저장한다. 상담(`ui/editor/consult.ts`)이 이미 id 로 맞추는 선례.
- **같이 바뀌는 곳**: 저장 부르는 곳 111군데 중 「답을 기다린 뒤 저장」하는 곳만 id 를 넘긴다. 나머지는 지금처럼.
- **나쁜 점**: 번호가 밀린 드문 경우에만 채팅을 몇 개 더 읽는다.

### 5. 지우거나 ◀▶ 로 고른 응답에 맞춰 상황판을 읽기 — R18, R19
- **무엇**: 응답을 지운 직후(다음 말 전까지) 상황판이 지운 응답의 괴이를 「발생 중」으로 보인다. 다시 굴린 뒤 ◀ 로 앞 답을 고르면 그 앞 답의 출동이 없던 일이 된다(그 답의 태그는 첫 처리 때 본문에서 걷혀 다시 못 읽음).
- **고치는 법**: 지금은 「마지막 응답 바로 앞 상태」 하나만 둔다. 이것을 「그 자리 응답마다, 반영한 뒤 상태」까지 적어 두는 것으로 넓힌다(같은 자리 응답 몇 개만, 다음 자리로 넘어가면 버림). 상황판 상태를 읽는 함수 하나(`readWorld` 대신 「지금 살아 있는 응답에 맞는 상태」)를 만들어 화면·요청 조립·다음 응답 처리가 모두 그것을 쓴다. 지운 응답이면 그 앞 상태, ◀ 로 고른 앞 응답이면 그 응답을 반영한 뒤 상태.
- **같이 바뀌는 곳**: 상황판 창·임무 창·지도·요청 조립·응답 처리. 손으로 끝낸 상황(D-04)은 지금처럼 기준 상태에도 같이 적어 남긴다. 인물 기록 쪽 ◀ 문제(R19 뒷부분)는 이번엔 안 다룬다(갱신기가 다음 턴에 다시 맞춤, 모델 운). 따로 여쭐 것.
- **나쁜 점**: 채팅 변수에 상태 사본이 몇 개 더 남는다(같은 자리 응답 수만큼, 보통 1~3개).

### 6. 응답을 지우면 바로 다시 그리기 — R34, R40, R45(일부)
- **무엇**: 지운 뒤 「다음 메시지에 사용」 칩이 안 보이고(R34), 지운·다시 굴린 응답이 만든 인물이 다음 갱신까지 목록·Router 명단에 남는다(R40).
- **고치는 법**:
  - R40: 인물 목록·Router 명단을 만들 때(읽을 때) 「살아 있는 응답에서 나온 인물만」 거른다. 소지품·가계부가 이미 쓰는 방식(살아 있는 응답만 골라 보여 줌)과 같다. 저장 안의 정리(dropGonePeople)는 그대로 두고, 같은 판정을 읽는 쪽에서도 쓴다.
  - R34: 1초 감시가 열린 채팅의 메시지 수를 같이 보고(리스AI 화면의 메시지 칸 수), 줄었으면 사용 칩을 다시 그린다(refreshUseBox). 이 감시가 지움을 알아채는 유일한 곳이 된다.
- **나쁜 점**: R34 는 1초 감시가 화면의 메시지 칸을 한 번 더 센다.

- **R54 직접 만든 조직을 기본 정보 「지우기」로 지우면 남음**: 기본 정보의 「지우기」가 머리 「삭제」와 같은 지우기 함수를 부른다.
- **R55 점검 「초기화」 해도 명부 칸은 그대로**: 초기화가 명부 고친 값도 설치 기본값으로 되돌린다(K-01 「초기화는 전체 초기화」). 기준 = 설치 자료의 명부.
- **R60 위키 매 턴 호출이 다음 턴 기록에 섞임**: 호출 주인 판정(`core/progress.ts` callOwner)이 「응답 받기 전」만 보지 않고, 호출이 어느 턴에서 시작됐는지(시작할 때 턴 번호)를 적어 그 턴에 붙인다.
- **R61 화면 읽기에서 「호출 진행 창이 기기」**: 켬끔 단추 이름을 만들 때 「이 기기」 배지(.gx-scope)를 뺀 글만 쓴다(`ui/controls.ts`).
- **R62 점검 페이지를 옮겨도 앞 안내가 남음**: 페이지 옮기기(ed-node)에서 그 페이지 안내(manUi.info)를 지운다. 다른 페이지와 같은 규칙.
- **R63 주인공 이미지 켬 + 페르소나 사진 없음 → 큰 빈 네모**: 페르소나 태그의 대신 그림(유저 사진)은 사진이 있을 때만. 없으면 칸을 안 그린다(사용자 10-26 「목록에 없으면 칸을 그리지 않는다」). 요원으로 플레이하지 않을 때는 User 를 그림 이름 목록에 넣지 않는다(설정 도움말대로).
- **N01 「소속을 정하지 않은 요원이 N명」 눌러도 안 감**: 거점 페이지를 그릴 때 목록 종류를 「거점」으로 되돌리는 줄(`ui/editor/index.ts:787`)이 단추가 바꾼 값을 덮지 않게, 페이지를 처음 열 때만 정한다.
